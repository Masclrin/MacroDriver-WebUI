# 执行引擎架构

## 1. 核心数据结构

### 1.1 ExecContext（执行上下文）

全局唯一的执行上下文，贯穿整个自动化执行生命周期。

```python
class ExecContext:
    graph: ExecGraph              # 编译后的图
    stop_event: threading.Event   # 全局停止信号
    pause_event: threading.Event  # 全局暂停信号
    variables: dict               # 全局变量表（线程安全）
    check_results: dict           # 检测结果缓存（线程安全）
    task_pool: TaskPool           # 异步任务池
    monitors: list                # 活跃监视器列表
    last_capture_cache: dict      # 截图缓存（用于帧差比对）
    hwnd_cache: dict              # 窗口句柄缓存
    interception_session          # Interception 驱动会话
    _profile: dict                # 当前执行档案配置
    _goto_target: str             # goto 跳转目标（主线程）
    _ocr_engine                   # OCR 引擎实例（复用）
    _capture_manager              # DXGI 截图管理器
    _data_lock: threading.RLock   # 全局数据锁
    errors: list                  # 错误日志
    _executed_nodes: set          # 已执行节点集合（主线程）
    _branches: dict               # 所有分支上下文
    _scopes: dict                 # 所有 Scope
    _join_events: dict            # Join 等待事件
    _join_arrivals: dict          # Join 到达记录
    _join_done_flag: dict         # Join 完成标记
    _affinity_tracker: dict       # 绑核追踪
    _race_events: dict            # Race 等待事件
```

### 1.2 BranchContext（分支上下文）

每个 Fork/Race 分支拥有独立的 BranchContext。

```python
class BranchContext:
    branch_id: str                # 分支唯一标识
    parent_ctx: ExecContext       # 父执行上下文
    fork_node_id: str             # 所属 Fork/Race 节点 ID
    parent_branch_id: str         # 父分支 ID
    scope_id: str                 # 所属 Scope ID
    child_scope_ids: list         # 子 Scope ID 列表
    thread: threading.Thread      # 分支线程
    stop_event: threading.Event   # 分支停止信号
    pause_event: threading.Event  # 分支暂停信号
    _status: str                  # running/completed/error/cancelled
    affinity_config: dict         # 绑核配置
    _executed_nodes: set          # 分支内已执行节点
    _goto_target: str             # 分支内 goto 目标
    _current_affinity: int        # 当前绑核核心
```

### 1.3 Scope（并发作用域）

每个 Fork/Race 节点创建一个 Scope，管理其所有分支。

```python
class Scope:
    scope_id: str                 # 作用域 ID
    fork_node_id: str             # 所属 Fork/Race 节点 ID
    parent_branch_id: str         # 父分支 ID
    branch_ids: list              # 包含的分支 ID 列表
    child_scope_ids: list         # 子 Scope ID 列表
    status: str                   # running/completed/cancelled
    winner_branch_id: str         # Race 胜出分支 ID
```

### 1.4 TaskPool（异步任务池）

管理 `call_script_async` 启动的异步宏任务。

```python
class TaskPool:
    tasks: dict                   # task_id → AsyncTask
    start(node_id, compiled, ...) # 启动异步任务
    stop(task_id)                 # 停止指定任务
    stop_all()                    # 停止所有任务
    pause(task_id)                # 暂停指定任务
    resume(task_id)               # 恢复指定任务
```

## 2. 执行流程

### 2.1 入口

```
execute_graph(graph, stop_event)
  → 注册所有 handler
  → 创建 ExecContext
  → 根据 graph.settings.execution_profile 初始化 InterceptionSession
  → _execute_node(graph.entry_node_id, ctx)
  → finally: 释放修饰键、停止所有任务、清理分支线程
```

### 2.2 节点执行循环

```
_execute_node(node_id, ctx)
  → 检查是否已执行（防重复）
  → 确保数据输入就绪（递归执行上游数据节点）
  → 进入 goto 循环（最多 100000 次迭代）
    → 检查停止/暂停信号
    → 解析节点参数中的变量引用
    → 清除 goto 目标
    → 调用 handler(node, ctx)
    → 捕获异常并记录
    → 检查 goto 目标，如有则跳转
```

### 2.3 流程执行

```
_execute_flow(node_id, port_name, ctx)
  → 收集上游输出数据
  → 设置线程本地存储（upstream_outputs, upstream_node_id）
  → 遍历 port_name 对应的下游节点
    → _execute_node(child_id, ctx)
```

## 3. 线程模型

### 3.1 线程本地存储

使用 `threading.local()` 存储每个线程的：
- `branch_id`：当前分支 ID
- `current_affinity`：当前绑核核心
- `upstream_outputs`：上游节点输出
- `upstream_node_id`：上游节点 ID

### 3.2 绑核机制

- Fork/Race 分支支持独立绑核（`branch_affinity_N` 参数）
- 使用 `set_thread_affinity` / `clear_thread_affinity`
- 绑核在分支线程启动时设置，结束时清除

### 3.3 线程安全

- 所有共享数据访问通过 `ctx._data_lock` (RLock) 保护
- 变量读写使用 `safe_set_variable` / `safe_get_variable`
- 检测结果使用 `safe_set_check_result` / `safe_get_check_result`

## 4. 错误处理

### 4.1 错误收集

```python
ctx.log_error(message, node_id=None, error_type="system")
```

错误类型：
- `system`：系统级错误（节点不存在、处理器未注册）
- `runtime`：运行时错误（节点执行异常）
- `plugin`：插件执行错误

### 4.2 错误展示

- 后端：错误存入 `ctx.errors` 列表
- 前端：通过 `get_automation_status` 轮询，状态为 `error` 时以 Toast 弹窗展示最后一条错误

### 4.3 异常隔离

- 每个节点 handler 的异常被独立捕获，不影响后续节点
- 分支线程异常不影响其他分支
- 插件异常不影响主引擎

## 5. 旧引擎集成

### 5.1 模块加载

```python
_get_old_engine() → 查找已加载的 "宏执行框架3_2" 或 "macro_executor_v23" 模块
```

### 5.2 调用方式

| 节点 | 调用方式 | 阻塞 |
|------|----------|------|
| `call_script_sync` | `execute_macro_once` 或直接执行闭包 | 是 |
| `call_script_async` | `TaskPool.start` → `execute_macro_once` | 否 |

### 5.3 短路径优化

当编译后宏 ≤ 2 步时，`call_script_sync` 直接执行闭包函数，跳过旧引擎的 trace/lag/random/batch 等特性。这是有意的优化——单个动作对时间要求不高。

### 5.4 参数传递

新引擎传递的 options：
```python
{
    "speed_factor": float,        # 节点参数或默认 1.0
    "timeline_mode": str,         # 节点参数或默认 "absolute"
    "random_delay": bool,         # 节点参数或默认 False
    "auto_release_modifiers": False,  # 新引擎自己管理修饰键
}
```

其余参数（low_cpu、batch_send、test_trace、lag_compensation 等）fallback 到旧引擎全局变量，用户通过全局参数页的 `executor` section 修改。

## 6. 编译缓存

- 缓存粒度：`(file_path, os.path.getmtime(file_path))`
- 缓存位置：内存（非磁盘，磁盘读写太慢）
- 生命周期：一次自动化执行期间（ExecContext 级别）
- 目的：避免同一宏被循环调用时重复编译
