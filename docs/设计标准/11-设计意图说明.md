# 设计意图说明

> 本文档记录项目中有意为之的设计决策，避免后续审查将其误报为缺陷。

## 1. 执行模型

| 行为 | 说明 |
|------|------|
| `flow/end` 全局终止 | 任何分支到达结束节点 = 任务完成。如仅需结束当前分支，使用 `control/stop_branch` |
| Fork `done` 端口 | 简单场景自动汇合，复杂场景用 Join |
| Race 分支自然结束 = 胜出 | 不需要 `race_win` 也能胜出 |
| `call_script_sync` ≤2 步短路径 | 有意优化，跳过旧引擎开销 |
| 监视器后台线程不响应暂停 | 监视器模型不允许暂停恢复；延迟/等待节点暂停后恢复时跳过剩余等待时间 |

## 2. 变量与数据

| 行为 | 说明 |
|------|------|
| 变量全局共享 | 用户自行管理命名，避免并发冲突。不设分支局部变量 |
| `var_compare` 自动类型推断 | 先数字比较，失败则字符串比较，减少手动转换 |
| `store_var` 等输出变量标记 `varRef` | 允许用户通过 `$` 按钮选择已有变量覆盖，或使用 `${动态变量名}` 运行时决定存储目标 |
| `var_math` 除零返回 0 | 容错设计：除零记录错误日志但返回 0 继续执行，避免整个自动化任务中断 |
| 工具节点隐式 `_out` 变量 | 常量/运算节点自动创建 `{id}_out` 变量存储结果，方便下游引用 |
| 书签坐标实时解析 | window/relative 模式每次查询窗口位置，窗口拖动后坐标自动跟随 |

## 3. 节点设计

| 行为 | 说明 |
|------|------|
| `goto` 使用 `varRef` 而非 `nodeRef` | goto 目标通常由运行时逻辑决定，固定下拉选择意义不大 |
| 起始/结束节点颜色特殊化 | flow 分类颜色与 flow/start/end 节点颜色不同，强调起始/结束节点的特殊性 |
| 复制粘贴仅保留内部连线 | 粘贴节点时仅保留被复制节点之间的连线，连到外部节点的连线不保留 |
| 监视器 `absent` 触发模式 | 不要求先检测到目标再判定"消失"，只要当前帧未检测到即触发。与 `disappear`（从有到无）语义不同 |
| `preset_find_click`/`preset_read_text` 异常时停止执行 | 运行时错误（截图失败、模板损坏等）报错并停止，而非静默走 not_found/next 分支 |

## 4. 坐标系统

| 行为 | 说明 |
|------|------|
| window 模式存储物理像素 | 2026-05 重构：从「逻辑坐标 + DPI 双向转换」改为「物理坐标直存」，消除 DPI 不一致风险 |
| relative 模式显示比例值 | 显示 0.5 比 960px 更清晰，跨分辨率自动适配 |
| 坐标浏览器是浮动面板 | 弹出窗口无法访问主窗口状态，浮动面板满足所有需求 |

## 5. 并发与线程安全

| 行为 | 说明 |
|------|------|
| `check_results` 无锁直接访问 | Python GIL 提供基本保护；加锁增加每次访问开销，影响执行精度。实际触发概率极低 |
| `node.params` 并发修改 | executed_set 机制保证同一节点不会被两个线程同时执行 |
| `InterceptionSession` 全局单例 | 懒加载，不持有需显式释放的资源 |
| `TaskPool._propagate_stop` 空转 | daemon 线程不阻止进程退出，50ms 轮询开销极小 |

## 6. 前端

| 行为 | 说明 |
|------|------|
| `_registerFallback` 硬编码 schema | 仅在 API 调用失败/浏览器开发模式时使用，正常流程从后端获取 |
| `_checkShowWhen` 两处实现 | utils.js（节点内联）和 renderers.js（属性面板），修改时必须同步 |
| `_safe_bool` 统一布尔转换 | 所有布尔参数解析应使用此函数 |
