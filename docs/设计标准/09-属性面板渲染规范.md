# 属性面板渲染规范

## 一、问题根因

前端 `webui/modules/auto/core/nodes.js` 中的 `_registerFallback()` 函数包含了**所有内置节点的硬编码 `params_schema`**。

### 触发场景

| 场景 | 使用的 schema 来源 |
|------|-------------------|
| pywebview API 调用成功 | 后端 `PluginRegistry.get_frontend_payload()` → `_registerFromPayload()` |
| pywebview API 调用失败 | `_registerFallback()` 硬编码 schema |
| 浏览器开发模式（无 pywebview） | `_registerFallback()` 硬编码 schema |

当日 `_registerFallback()` 回退时，如果其中的 `params_schema` 与后端不一致，新增的参数字段就不会渲染。

## 二、强制规范

**凡是新增或修改后端节点参数，必须同步更新三处：**

| 序号 | 位置 | 文件 | 格式约定 |
|------|------|------|---------|
| ① | 后端节点定义 | `automation/nodes/<category>.py` | Python，用 `description` / `enum` |
| ② | 前端 fallback | `webui/modules/auto/core/nodes.js` 中 `_registerFallback()` 内 | JS，用 `label` / `options` |
| ③ | 后端 handler | `automation/handlers/<category>.py` | 读取并使用新参数的逻辑 |

## 三、参数格式对照

| Python 后端 | JS 前端 fallback |
|-------------|-----------------|
| `"type": "boolean"` | `type: 'bool'` |
| `"type": "string", "enum": ["a", "b"]` | `type: 'enum', options: ['a', 'b']` |
| `"description": "说明文字"` | `label: '说明文字'` |
| `"showWhen": "key=True"` | `showWhen: 'key=true'`（注意小写！） |
| `"display_names": {"a": "A标签"}` | `display_names: {'a': 'A标签'}` |
| `"default": True` | `default: true` |
| `"default": 0` | `default: 0` |
| `"varRef": True` | `varRef: true` |
| `"nodeRef": "typeA,typeB"` | `nodeRef: 'typeA,typeB'` |
| `"format": "region"` | `type: 'region', coordMode: true` |
| `"format": "path"` | `type: 'path', browseType: '...'` |
| `"minimum": 0, "maximum": 1` | （前端 `_renderNumberField` 不强制使用 min/max，可省略） |

## 四、showWhen 注意事项

`_normalizeSchema` 函数会自动将 showWhen 中的 `=True` / `=False` 转换为小写 `=true` / `=false`。

因此 Python 后端可以用 `showWhen: "key=True"`（大写），前端 fallback **应该用小写** `showWhen: 'key=true'`。

## 五、nodeRef 迁移注意事项

当节点 type 发生变更时（如 `preset/preset_sub_script` → `action/exec_sub_script`）：

1. 更新端口名映射表（`_portNameMap`，约第 48 行）
2. 更新 fallback 定义中的 type、category、color
3. 更新所有其他节点 param_schema 中的 `nodeRef` 引用（添加新 type，保留旧 type 以兼容）

## 六、快捷面板（Inline Panel）字段渲染与同步规范

**快捷面板** = 节点卡片上的内联字段（class `nf`），用户无需打开属性面板即可直接编辑。

**属性面板** = 右侧详细面板（id `property-panel-content`），提供更全面的编辑功能。

两个面板的同步机制涉及 **渲染层** 和 **事件层**，共 4 个文件。

### 6.1 渲染规范：`data-key` / `data-nid` 归属规则

**所有 `nf` 字段必须遵守：`nf` class、`data-key`、`data-nid` 三者位于同一个 DOM 元素上。**

这是因为 `_bindInlineFields`（node-renderer.js）和两个 `_sync*` 函数（events.js / interactions.js）都使用选择器 `.nf[data-key="..."]` 查找目标字段。

**正确示例**（enum、number、string、color）：

```html
<select class="nf nf-sel" data-nid="42" data-key="mode">      ✓同一个元素</select>
<input type="number" class="nf nf-num" data-nid="42" data-key="delay"> ✓</select>
```

### 6.2 布尔（bool）字段的特殊处理

`bool` 类型的渲染函数在 `webui/modules/auto/core/utils.js` 的 `_renderInlineField()` 中，输出结构为：

```html
<label class="nf nf-chk" data-nid="42" data-key="enabled">   ← nf + data-key 在 label
  <input type="checkbox">                                      ← 内部不含 data-key
  <span class="chk-mk"></span>
</label>
```

**绝对禁止**将 `data-key` / `data-nid` 放在内部的 `<input>` 上，否则 `.nf[data-key="..."]` 选择器将找不到任何元素。

### 6.3 事件绑定规范

`webui/modules/auto/render/node-renderer.js` 的 `_bindInlineFields()`函数遍历 `.nf`元素时，**必须为 `f.tagName === 'LABEL'` 添加独立的分支**，因为 `LABEL` 不是 `SELECT` / `INPUT`，不会匹配 `f.type === 'checkbox'`。

添加 `bool` 字段时必须检查并同步更新此处。

### 6.4 同步函数规范

**属性面板向快捷面板同步**由两个函数完成，它们都使用 `.nf[data-key="..."]` 查找快捷面板上的元素：

| 函数 | 文件 | 触发时机 |
|------|------|---------|
| `_syncInlineField()` | `events.js` `_bindEvents()` 内部闭包 | 属性面板任意字段的 input/change 事件 |
| `_syncNodeInlineField()` | `interactions.js` 开放方法 | 快捷键选择器（key selector / var selector）操作后 |

两个函数 `if-else` 链中都必须包含 `LABEL` 分支：

```javascript
} else if (field.tagName === 'LABEL') {
    var cb = field.querySelector('input[type="checkbox"]');
    if (cb) cb.checked = (value === true || value === 'true');
}
```

不允许依赖 `else { field.value = value; }` 兜底——`<label>` 元素没有 `value` 属性。

### 6.5 受影响的渲染层级

```mermaid
flowchart TD
    A[params_schema\n中声明 type:'bool'] --> B[_renderInlineField\nutils.js]
    B --> C[生成 label.nf>input[checkbox]\ndata-key 在 label 上]
    C --> D[._bindInlineFields\nnode-renderer.js]
    C --> E[._syncInlineField\nevents.js]
    C --> F[._syncNodeInlineField\ninteractions.js]
    D --> G{是否有 f.tagName==='LABEL' 分支?}
    G -->|无| H[checkbox 点击事件不绑定\nnode.properties 不更新]
    E --> I{是否有 LABEL 分支?}
    F --> I
    I -->|无| J[属性面板修改不反映到\n快捷面板 checkbox]
```

### 6.6 已知历史问题（2026-05 修复）

`bool` 类型字段的 `data-key` / `data-nid` 被错误放在 `<input>` 上，同时 `_bindInlineFields`、`_syncInlineField`、`_syncNodeInlineField` 三处均缺失 `LABEL` 分支处理，导致约 22 种节点（如 `flow/start`、`detection/check_ocr`、`control/join`、`monitor/monitor_color` 等）的布尔开关在快捷面板和属性面板之间完全无法同步。

## 七、坐标参数渲染规范

### 7.1 coordMode 分组

`params_schema` 中标记 `coordMode: true` 或 `coordRef: true` 的参数，在属性面板中自动归入「坐标」分组，其余归入「参数」分组。

分组逻辑位于 `property/index.js`（第 53-70 行）：

```javascript
var coordParams = [];
var mainParams = [];
for (var key in schema) {
    var s = schema[key];
    if (s.coordRef || s.coordMode) {
        coordParams.push([key, s]);
    } else {
        mainParams.push([key, s]);
    }
}
```

**自动标记规则**（`nodes.js` `_normalizeSchema`）：
- `mode` 字段如果是 enum 且同时包含 `screen` 和 `window` 选项 → 自动标记 `coordMode: true`
- `rect`/`region` 字段类型为 `region` → 自动标记 `coordMode: true`、`varRef: true`
- `hwnd_var` 字段 → 自动标记 `varRef: true`，若已有 coordMode 标记则也标记 `coordMode: true`

### 7.2 region 字段渲染（2026-05 更新）

`_renderRegionField`（`renderers.js`）根据当前坐标模式决定显示值：

| 模式 | 存储值 | 显示值 | 标记 |
|------|--------|--------|------|
| `screen` | 物理像素 | 原样显示 | 无特殊标记 |
| `window` | **物理像素**（2026-05 重构后） | 原样显示 | 无 `data-phys-display` |
| `relative` | 0~1 归一化值 | 原样显示，步长 `0.01` | 无特殊标记 |

**2026-05 重构说明**：window 模式从「逻辑坐标存储 + DPI 双向转换」改为「物理坐标直存」。`data-phys-display` 和 `dpiScale` 相关转换已全部移除。

### 7.3 坐标拾取器转换（2026-05 更新）

拾取器（`pickers/tools.js`）的 `calcLogicCoords` 函数根据 `coordMode` 转换拾取到的物理像素：

| 模式 | 转换逻辑 |
|------|---------|
| `screen` | `origin + pixel` → 物理坐标直存 |
| `window` | `pixel` → **物理坐标直存**（不再除以 dpiScale） |
| `relative` | `pixel / virtualSize` → 0~1 归一化存储 |

区域拾取同理：
- `screen`：`[origin+x, origin+y, w, h]`
- `window`：`[x, y, w, h]`（物理像素直存，不再除以 dpiScale）
- `relative`：`[x/virtualW, y/virtualH, w/virtualW, h/virtualH]`

### 7.4 DPI 缩放获取

`window._screenDpiScale` 由后端通过 `pywebview.api.get_dpi_scale()` 获取并缓存。属性面板渲染时若 DPI 缩放尚未就绪，会在就绪后重新渲染。

### 7.5 坐标参数设计规范

新增涉及截图/检测的节点时，必须遵守：

- [ ] `mode` 参数使用 `enum` 类型，选项 `['screen', 'window', 'relative']`，标记 `coordMode: true`
- [ ] 所有 `region` 类型参数标记 `coordMode: true`
- [ ] `hwnd_var` 参数标记 `varRef: true`，`showWhen` 条件为 `mode=window` 或 `mode=relative`
- [ ] 默认值基于 1920×1080 物理分辨率计算
- [ ] 后端统一使用 `resolve_region(mode, rect, hwnd)` 转换坐标

## 八、检查清单

修改/新增节点参数时，逐项确认：

- [ ] 后端 `nodes/<cat>.py` 的 `register()` 中添加了 `params_schema` 字段
- [ ] 前端 `nodes.js` 的 `_registerFallback()` 中对应 type 的 `params_schema` 已同步
- [ ] 后端 handler 已实现新参数的读取和处理逻辑
- [ ] 所有 `nodeRef` 引用（如有涉及 type 变更）已全部更新
- [ ] `Grep` 搜索旧 type 名称，确认无遗漏引用
- [ ] **若新增 `type:'bool'` 参数，同步检查 4 处代码：** `utils.js` `_renderInlineField`（渲染）、`node-renderer.js` `_bindInlineFields`（事件绑定）、`events.js` `_syncInlineField`（属性→快捷同步）、`interactions.js` `_syncNodeInlineField`（选择器同步）
- [ ] Python 编译通过（`py_compile.compile` 对每个修改的 .py 文件）
- [ ] JS 语法检查通过（`node --check` 对每个修改的 .js 文件）
- [ ] **若新增坐标参数（region/rect），确认**：`coordMode: true` 已标记、`mode` 参数选项含三种模式、`hwnd_var` 标记 `varRef: true`、后端使用 `resolve_region` 转换、window 模式下属性面板**原样显示物理像素**（不再做 DPI 转换）
