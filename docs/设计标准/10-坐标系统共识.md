# 坐标系统共识与设计决策

> 本文档记录 2026-05 坐标系统重构过程中的关键设计决策、已修复问题、以及后续开发/审查的指导原则。
> 所有涉及坐标系统的代码修改必须遵守本文档。

***

## 一、坐标模式存储模型（核心决策）

### 1.1 三种模式的存储约定

| 模式         | 存储值          | 属性面板显示           | 执行时转换                           | 设计理由                                         |
| ---------- | ------------ | ---------------- | ------------------------------- | -------------------------------------------- |
| `screen`   | **物理像素**（整数） | 原样显示             | 直通 `int(x), int(y)`             | 物理坐标最直观，所见即所得                                |
| `window`   | **物理像素**（整数） | 原样显示             | `cx + x, cy + y`（窗口客户区原点 + 存储值） | 2026-05 重构：从「逻辑坐标」改为「物理坐标」存储，消除 DPI 双向转换的复杂性 |
| `relative` | **0\~1 比例值** | 原样显示（如 0.5, 0.3） | `cx + x*cw, cy + y*ch`          | 比例语义清晰，跨分辨率适配。保持比例显示，不改                      |

### 1.2 为什么 window 模式改存物理坐标？

**旧模型（已废弃）：**

```
拾取器: px / dpiScale → 存储逻辑坐标
属性面板: 逻辑坐标 * dpiScale → 显示物理坐标（给用户看）
执行时: 逻辑坐标 * dpiScale + 窗口原点 → 物理坐标
```

问题：双向转换容易因 DPI 不一致、跨屏移动、浮点精度导致偏差。

**新模型（当前）：**

```
拾取器: px → 直接存储物理坐标
属性面板: 原样显示物理坐标
执行时: 存储值 + 窗口原点 → 物理坐标
```

优势：存储=显示=执行，三者统一，无 DPI 转换。

### 1.3 relative 模式保持 0\~1 比例（不改）

relative 模式的核心语义就是「比例」。显示比例值（如 0.5）比显示换算后的物理像素更清晰。跨分辨率时比例自动适配，这是设计考虑，**不改为物理像素显示**。

## 二、坐标浏览器架构

### 2.1 浮动面板模式（当前）

坐标浏览器是主窗口内的**浮动面板**（`#coord-overlay-float`），不是弹出窗口。

```
主窗口
├── 编辑器画布
├── 属性面板
└── 截图坐标浮动面板（可拖拽、可关闭）
```

### 2.2 弹出窗口模式（已弃用）

`webui/coord_overlay_popout.html` 已标记为 **DEPRECATED**。该文件保留仅作参考，后续可安全删除。

弃用原因：

- 弹出窗口无法访问主窗口的 `window.AutomationApp` 状态
- graph\_json 缓存同步复杂，容易出现延迟和不同步
- 浮动面板已满足所有需求，无需独立窗口

### 2.3 坐标浏览器中的截图方式

| 截图方式       | 全部显示器                                        | 单显示器（显示器N）               |
| ---------- | -------------------------------------------- | ------------------------ |
| **MSS**    | ✅ 虚拟桌面截图                                     | ✅ 单显示器截图                 |
| **BitBlt** | ✅ 虚拟桌面截图                                     | ✅ 单显示器截图                 |
| **DXGI**   | ❌ 不支持 → 自动用 MSS 截图，状态栏提示「mss (DXGI不支持全部显示器)」 | ✅ Desktop Duplication 截图 |

**设计原则**：用户可以选择「DXGI + 全部显示器」，但后端实际用 MSS 截图并返回提示文字。不强制切换前端下拉框，保持用户选择状态。

## 三、截图方式与回退链

### 3.1 节点执行时的截图方式

```
context.capture_screen(region)
    ├── 有截图源节点(capture_source) → DXGI 后台采集
    │   └── DXGI 无帧 → BitBlt → MSS
    └── 无截图源节点 → BitBlt
        └── BitBlt 失败 → MSS
```

### 3.2 控制台日志

首次使用某种截图方式时，终端打印日志：

- `[截图] 使用 DXGI 后台采集 (截图源节点已连接)`
- `[截图] 使用 BitBlt 截图 (无截图源节点，BitBlt/MSS)`
- `[截图] DXGI 无帧，回退 BitBlt/MSS`（CaptureManager 中）

### 3.3 BitBlt 稳定性

BitBlt 使用 `CreateDIBSection` 替代 `CreateCompatibleBitmap`，避免大尺寸/高 DPI 下的内存分配失败。同时检测最小化窗口（坐标 -32000）并自动回退 MSS。

### 3.4 MSS 重试

MSS 截图失败时（如 `GetDIBits failed`），自动重试最多 3 次，每次失败后重置 MSS 实例并递增等待时间（100ms/200ms/300ms）。

## 四、坐标浏览器叠加显示

### 4.1 四者统一目标

```
坐标浏览器显示 ←→ 拾取器框选 ←→ 属性面板坐标 ←→ 节点执行位置
```

当前状态（window 模式物理存储后）：

- ✅ 拾取器框选 → 存储物理坐标
- ✅ 属性面板 → 显示物理坐标
- ✅ 节点执行 → `cx + x`（物理坐标 + 窗口原点）
- ✅ 坐标浏览器 → 根据模式解析后叠加显示

### 4.2 缓存机制

坐标浏览器使用后端缓存 `self._last_overlay_graph_json` 获取当前流程图状态：

1. 前端 `onGraphChange` 回调中调用 `cache_overlay_graph_json(jsonStr)`
2. 后端更新缓存
3. 坐标浏览器每次刷新从缓存读取

**所有属性修改必须触发** **`_notifyGraphChange()`**，否则缓存不同步。已在以下位置添加：

- `property/events.js`：number/region/select/bool 输入事件
- `pickers/tools.js`：`_fillCoordInput` / `_fillRegionInput`

### 4.3 overlay 绘制内存保护

`_draw_coord_overlays` 中：

- overlays 为空时跳过绘制（避免不必要的内存分配）
- PIL 路径仅在标签含中文时启用（减少 `cvtColor` 内存开销）
- `cv2.cvtColor` 内存不足时捕获异常，跳过 overlay 绘制并打印警告

## 五、已知遗留问题（后续修复指南）

### 5.1 自动化执行路径的 DXGI 多屏（已修复 2026-05）

**修复内容**：

- `DXGICapture`：移除单例模式，每个 `output_idx` 创建独立 `_DXGICaptureImpl`，支持多显示器并发采集
- `CaptureManager`：`_dxgi_running_keys` 改为集合，支持多个 DXGI 输出同时运行
- `CaptureManager._find_best_dxgi(region)`：根据 region 坐标自动路由到对应的 DXGI 输出
- `CaptureManager.capture()`：修复坐标转换BUG，传入 `get_region_frame` 前减去 `output_origin`
- `capture_source` 节点：废弃 `capture_mode`/`region` 参数，新增 `monitor_index` 参数
- `capture_source` handler：`enabled=false` 时只停止对应 `monitor_index` 的 DXGI，不影响其他
- `capture_screen()`：返回值改为 `(img, method)` 元组，日志在截图方式变化时打印
- `mss_index_to_dxgi_output()`：通过 `EnumDisplayMonitors` 坐标匹配确保 mss 索引与 DXGI output_idx 一致
- `check_screen` 节点：新增 `frozen_duration_ms` 参数，替代硬编码 50ms 间隔
- `_image_match_cache`：加 `RLock` 保护并发读写

### 5.2 插件节点坐标不提取

`_extract_plugin_coord_rules` 只检测 4 元组 region，不检测单独的 x/y point。插件节点的坐标不会在坐标浏览器上显示标记。

**修复方向**：扩展 `_extract_plugin_coord_rules`，检测 `x`/`y` 数字字段对并配对为 point overlays。

### 5.3 window 模式跨 DPI 显示器移动

如果窗口在拾取后移动到另一个 DPI 不同的显示器，执行位置会偏移。

**建议修复**：节点执行时用 `GetDpiForWindow(hwnd)`（Win10 1607+）获取窗口实际 DPI，而非基于坐标推断。

注：为边界问题，可暂缓

### 5.4 坐标一致性校验机制

缺少自动化测试验证「拾取器 → 属性面板 → 浏览器 → 节点执行」四者坐标一致。

**建议**：增加调试端点 `validate_coordinate_pipeline`，输入已知坐标，经过完整链路后比较输出。

## 六、Bug 审查检查清单

审查坐标系统相关代码时，逐项确认：

- [ ] **存储模型**：window 模式是否存储物理坐标（而非逻辑坐标）？
- [ ] **DPI 转换**：是否还有未移除的 `* dpiScale` 或 `/ dpiScale`？
- [ ] **缓存同步**：属性修改是否触发 `_notifyGraphChange()`？
- [ ] **截图回退**：BitBlt/MSS/DXGI 回退时是否打印日志？
- [ ] **坐标浏览器**：DXGI + 全部显示器是否返回提示而非静默切换？
- [ ] **overlay 绘制**：空 overlays 是否跳过？内存不足是否保护？
- [ ] **relative 回退**：无 hwnd 时是否用 `GetSystemMetrics` 而非硬编码 1920×1080？
- [ ] **多屏原点**：DXGI 截图的 `origin_x/y` 是否与 MSS 一致？
- [ ] **其他问题**：跳出框架，思考可能存在的其他问题，多角度考虑。
