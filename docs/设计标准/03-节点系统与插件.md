# 节点系统与插件机制

## 1. 节点注册表 (PluginRegistry)

### 1.1 概述

所有节点（内置和插件）通过 `automation/registry.py` 中的 `PluginRegistry` 统一注册和管理。

### 1.2 内置节点注册

```python
registry.register_node({
    "type": "category/node_name",
    "category": "action",          # action / detection / control / variable / utility
    "display_name": "中文显示名",
    "color": "#颜色",
    "inputs": [{"name": "in", "type": "flow"}],
    "outputs": [
        {"name": "next", "type": "flow"},
        {"name": "match", "type": "flow"},
        {"name": "no", "type": "flow"},
    ],
    "params_schema": {
        "param_name": {
            "type": "number",       # number / string / bool / enum / color / region / affinity
            "default": value,
            "min": 0,               # number 类型
            "max": 100,             # number 类型
            "options": [...],       # enum 类型
            "description": "参数说明",
            "varRef": True,         # 支持变量引用 ${var}
            "coordMode": True,      # 坐标相关参数
            "showWhen": "mode=window",  # 条件显示
        }
    },
    "handler": "_handle_xxx",       # 对应 handlers 中的函数名
    "dynamic_branches": True,       # 动态分支（Fork/Race）
})
```

### 1.3 前端节点定义获取

前端通过 API `get_node_definitions` 获取所有节点定义，动态渲染节点面板和属性面板。

## 3. Handler 注册

每个节点的 handler 函数在 `automation/handlers/` 目录下按模块组织：

| 模块 | 文件 | 负责节点 |
|------|------|----------|
| 动作 | `action.py` | mouse_click, key_action, mouse_scroll, text_input, wait, window_manage |
| 检测 | `detection.py` | check_color, check_ocr, check_image, check_screen, capture_source |
| 监视器 | `monitor.py` | monitor_color, monitor_ocr, monitor_timer |
| 控制 | `control.py` | if_else, loop_count, loop_while, wait_cond, seq_check, state_machine, goto, fork, join, race, race_win, stop_branch, pause_branch, resume_branch, call_script_sync, call_script_async |
| 变量 | `variable.py` | var_set, var_math, var_compare, var_string, var_convert |
| 预设 | `preset.py` | preset_click, preset_find_click, preset_read_text |

所有 handler 通过 `register_all_handlers()` 统一注册到 `NODE_HANDLERS` 字典。

## 4. 插件系统

### 4.1 插件结构

每个插件是一个独立目录，包含三个文件：

```
plugins/插件名/
  ├── manifest.json    # 元信息与节点列表
  ├── node.js          # 前端节点定义（参数、端口、回调）
  └── backend.py       # 后端执行逻辑
```

**三层通信：**
- **后端加载**：`PluginManager.scan(plugins/)` 扫描目录 → 读取 `manifest.json` → 加载 `backend.py` → 调用 `register()`
- **前端加载**：浏览器调用 `pywebview.api.list_plugins()` → 获取 `node.js` → 执行 `window.__plugin_nodes__` → 注册到工具箱
- **运行时执行**：引擎遇到 `plugin/xxx` 节点 → `PluginManager.execute()` → `backend.py execute(action, params, context)` → `context.emit()` → 前端 `onPluginEvent()`

### 4.2 manifest.json

```json
{
  "id": "插件ID",
  "name": "插件名称",
  "version": "1.0.0",
  "nodes": ["action_name"],
  "node_display_names": { "action_name": "显示名" },
  "icon": "fa-solid fa-bell",
  "color": "#a855f7",
  "backend": "backend.py",
  "frontend": "node.js",
  "minAppVersion": "2.8"
}
```

> `nodes` 中是节点 type 后缀，完整 type 为 `plugin/xxx`。`node_display_names` 可选，覆盖默认显示名。

### 4.3 backend.py

```python
def register():
    return [{"action": "action_name", "name": "显示名"}]

def execute(action, params, context):
    if action == "action_name":
        return _handle(params, context)
    return {"ok": False, "error": f"未知动作: {action}"}
```

**返回值规范：**

| 返回值 | 说明 |
|--------|------|
| `{"ok": True}` | 成功，走 next/success 端口 |
| `{"ok": True, "set_variables": {"var": val}}` | 成功并设置全局变量 |
| `{"ok": True, "check_results": {"result": True}}` | 成功，数据端口输出 |
| `{"ok": True, "flow_port": "timeout"}` | 成功，走自定义出口端口 |
| `{"ok": False, "error": "原因"}` | 失败，走 fail 端口 |

**flow_port 自定义出口路由**：插件可通过返回值中的 `flow_port` 字段指定走哪个自定义输出端口，突破默认的 ok/success/fail/next 路由限制。路由优先级：
1. 返回值包含 `flow_port` 且节点定义了该端口 → 走指定端口
2. `flow_port` 指定的端口不存在 → 回退到 `next`
3. 无 `flow_port` → 按 `ok: true/false` → `success/fail/next` 逻辑

### 4.4 PluginContext API

插件执行时获得的上下文能力：

**事件与日志：**
| 方法 | 说明 |
|------|------|
| `context.emit(event, data)` | 向前端推送事件，前端 `onPluginEvent` 接收 |
| `context.log(level, msg)` | 写入日志，level: debug/info/warning/error |

**变量接口：**
| 方法 | 说明 |
|------|------|
| `context.get_variable(name, default)` | 读流程变量 |
| `context.set_variable(name, value)` | 写流程变量（跨插件共享） |
| `context.get_check_result(key, default)` | 读取检查结果 |

**截图/屏幕：**
| 方法 | 说明 |
|------|------|
| `context.capture_screen([x,y,w,h])` | 截图，参数为物理像素坐标，自动回退链：DXGI → BitBlt → mss |
| `context.get_screen_size()` | → `{"width": int, "height": int}` |

**窗口/UI：**
| 方法 | 说明 |
|------|------|
| `context.find_window(title, class_name)` | 返回 hwnd |
| `context.get_window_rect(hwnd)` | → `{"x","y","width","height"}` |
| `context.show_desktop_popup(title, msg, x, y, duration_ms)` | 桌面置顶弹窗 |

**输入/多媒体：**
| 方法 | 说明 |
|------|------|
| `context.get_mouse_position()` / `set_mouse_position(x,y)` | 鼠标位置 |
| `context.play_sound(file, freq, dur)` | 播放音频 |

**高精度等待：**
| 方法 | 说明 |
|------|------|
| `context.precise_sleep(seconds)` | 高精度等待（替代 `time.sleep`），三阶段混合等待+自适应补偿，自动响应停止/暂停事件 |

**图像检测：**
| 方法 | 说明 |
|------|------|
| `context.find_image(template, region, threshold)` | 模板匹配 |
| `context.check_color(x, y, color, tolerance)` | 颜色检测 |

> **兼容性**：所有接口可选，使用前用 `hasattr(context, 'xxx')` 检查可用性并为旧版本提供回退。

### 4.5 坐标系统约定（2026-05 更新）

所有涉及截图/检测的节点和插件，统一使用三种坐标模式：

| 模式 | 存储内容 | 属性面板显示 | resolve_region 转换 | 适用场景 |
|------|---------|-------------|---------------------|---------|
| `screen` | **物理像素坐标** | 原样显示 | 直通，不转换 | 全屏模式 |
| `window` | **物理像素坐标** | 原样显示 | `+ 窗口客户区原点` | 窗口模式 |
| `relative` | **0~1 归一化比例** | 显示比例值（如 0.5） | `× 窗口物理尺寸 + 原点` | 跨分辨率适配 |

**2026-05 重构说明**：window 模式从「逻辑坐标（物理÷DPI）」改为「物理坐标直存」，消除 DPI 双向转换的复杂性和不一致风险。relative 模式保持比例语义不变。

**坐标全链路**：
```
拾取器(tools.js)  → 物理像素直存 → 写入属性
属性面板(renderers.js) → 原样显示（window模式不再做DPI转换）
后端(coordinate.py) → resolve_region: 存储值 + 窗口原点 = 物理坐标 → capture_screen
```

**插件后端统一调用 `resolve_region`**：
```python
from engine.coordinate import resolve_region
phys_region = resolve_region(mode, rect, hwnd)
frame = context.capture_screen(list(phys_region))
```

**前端参数定义**：
```javascript
params_schema: {
  mode:     { type: 'enum', label: '坐标模式', default: 'screen',
              options: ['screen', 'window', 'relative'], coordMode: true },
  rect:     { type: 'region', label: '检测区域', default: [0,0,0,0], coordMode: true },
  hwnd_var: { type: 'string', label: '窗口变量', default: '', varRef: true }
}
```

> `coordMode: true` → 参数归入「坐标」分组，自动获得坐标拾取/框选按钮。
> `varRef: true` → 引擎自动解析 `${变量}` 引用。
>
> **坐标浏览器**：主窗口内的浮动面板（`#coord-overlay-float`），非弹出窗口。插件节点坐标标记显示需 `_extract_plugin_coord_rules` 提取（当前仅支持 region 4元组）。

### 4.6 varRef 自动解析

当 `params_schema` 中设置了 `varRef: true` 时，**引擎会自动解析** `${变量}` 引用，插件 `execute()` 收到的参数已经是解析后的值。未设置 `varRef: true` 的参数保持原始字符串，需手动解析。

### 4.7 showWhen 条件显示

`params_schema` 中支持 `showWhen` 条件显示表达式，控制参数在属性面板中的可见性：

- **运算符**：`=`、`!=`、`>=`、`<=`、`>`、`<`
- **多条件**：逗号分隔表示 AND
- **bool 类型**：使用小写 `true`/`false`

```javascript
threshold: { type: 'number', label: '阈值', showWhen: 'mode=manual' },
item_0:    { type: 'string', label: '项目1', showWhen: 'count>=1' }
```

### 4.8 插件管理

- `core/plugin_manager.py`：`PluginManager` 负责加载、卸载、执行插件
- 插件节点通过 `PluginRegistry` 注册，与内置节点统一管理
- 前端通过 API 获取插件节点定义，动态渲染
- 前端加载器：`webui/modules/auto/plugins/plugin-loader.js` 的 `loadPlugins()` 函数

## 5. 前端节点渲染

### 5.1 节点面板

- 按分类（category）组织节点
- 支持拼音搜索（如输入 "bingfa" 找到 "并发执行"）
- 拖拽节点到画布创建实例

### 5.2 属性面板

- 根据 `params_schema` 动态生成表单
- 支持条件显示（`showWhen`）
- 坐标参数支持可视化选取
- 变量引用支持 `${var}` 语法

### 5.3 动态分支

- Fork/Race 节点的分支端口根据 `branch_count` 参数动态增减
- 前端实时更新端口显示
