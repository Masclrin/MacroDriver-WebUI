# 变量与数据流

## 1. 变量系统

### 1.1 作用域

所有变量存储在 `ExecContext.variables` 中，**全局共享**。任何分支、任何节点都可以读写任意变量。

没有分支局部变量——这会导致用户困惑。用户需要自己管理变量命名，避免并发冲突。

### 1.2 内置变量

系统提供只读内置变量，以 `${变量名}` 语法引用：

| 变量名 | 值 | 示例 |
|--------|-----|------|
| `${timestamp}` | 毫秒时间戳 | 1712345678901 |
| `${timestamp_s}` | 秒时间戳 | 1712345678 |
| `${date}` | 日期 | 2025-01-15 |
| `${time}` | 时间 | 14:30:00 |
| `${datetime}` | 日期时间 | 2025-01-15 14:30:00 |
| `${datetime_compact}` | 紧凑日期时间 | 20250115_143000 |
| `${random}` | 随机数 | 42391 |
| `${random_int}` | 随机整数 | 784523 |
| `${year}` | 年 | 2025 |
| `${month}` | 月 | 01 |
| `${day}` | 日 | 15 |
| `${hour}` | 时 | 14 |
| `${minute}` | 分 | 30 |
| `${second}` | 秒 | 00 |
| `${weekday}` | 星期几 | 3 |
| `${pid}` | 进程 ID | 12345 |

### 1.3 变量引用语法

在节点参数中使用 `${变量名}` 引用变量：

```
x = ${target_x}
y = ${target_y}
delay = ${custom_delay}
```

### 1.4 变量初始化

在自动化脚本的 `variables` 字段中定义初始值：

```json
{
  "variables": {
    "target_x": { "init": 100 },
    "target_y": { "init": 200 },
    "boss_name": { "init": "巨龙" }
  }
}
```

## 2. 变量操作节点

### 2.1 `variable/var_set`（设置变量）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `name` | string | "" | 变量名（单变量模式） |
| `value` | string | "" | 变量值（支持 `${}` 引用） |
| `var_type` | enum | string | string / number / boolean |
| `vars_json` | json | "[]" | 多变量批量设置 |

多变量模式示例：
```json
[
  {"name": "x", "value": "100", "type": "number"},
  {"name": "y", "value": "200", "type": "number"},
  {"name": "name", "value": "目标", "type": "string"}
]
```

### 2.2 `variable/var_math`（变量运算）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `op` | enum | add | add/sub/mul/div/mod/min/max/abs/round |
| `a` | string | "0" | 操作数 A（支持 `${}` 和数据输入） |
| `b` | string | "0" | 操作数 B（支持 `${}` 和数据输入） |
| `store_var` | string | "" | 结果存储变量 |

### 2.3 `variable/var_compare`（变量比较）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `op` | enum | gt | eq/ne/gt/lt/ge/le |
| `a` | string | "0" | 比较值 A |
| `b` | string | "0" | 比较值 B |

**类型推断规则**：先尝试将两个值转为数字比较，失败则转为字符串比较。这减少了用户手动转换变量的步骤。

### 2.4 `variable/var_string`（字符串处理）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `op` | enum | concat | concat/substring/replace/split_index/regex_extract/upper/lower/trim |
| `a` | string | "" | 输入字符串 |
| `store_var` | string | "" | 结果存储变量 |

### 2.5 `variable/var_convert`（类型转换）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `to_type` | enum | number | number / string / boolean |
| `input_var` | string | "" | 输入变量 |
| `store_var` | string | "" | 结果存储变量 |

## 3. 数据流

### 3.1 流程连接 (Flow)

- 控制执行顺序
- 一个输出端口可以连接多个下游节点（并行执行）
- 一个输入端口可以接收多个上游连接（任一触发即执行）

### 3.2 数据连接 (Data)

- 传递检测结果、变量值
- 数据源节点必须先于目标节点执行
- 引擎自动确保数据依赖就绪（`_ensure_data_inputs`）

### 3.3 检测结果缓存 (`check_results`)

检测节点将结果写入 `ctx.check_results`，格式为 `{节点ID}.{端口名}`：

| 键 | 值 |
|-----|-----|
| `node1.result` | true/false |
| `node1.match_x` | 匹配 X 坐标 |
| `node1.match_y` | 匹配 Y 坐标 |
| `node1.text` | OCR 文字 |
| `node1.number` | OCR 数字 |
| `node1.color` | 检测到的颜色 |
| `node1.confidence` | 匹配置信度 |

其他节点通过数据连接读取这些结果。

### 3.4 上游输出传递

执行流程时，上游节点的 `check_results` 通过线程本地存储传递给下游节点，下游 handler 可通过 `ctx._get_upstream_outputs()` 获取。

## 4. 坐标书签系统

### 4.1 书签节点 (`utility/bookmark`)

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `name` | string | "" | 书签名（唯一标识） |
| `mode` | enum | screen | screen / window / relative |
| `x` | number | 0 | X 坐标 |
| `y` | number | 0 | Y 坐标 |
| `w` | number | 0 | 宽度 |
| `h` | number | 0 | 高度 |
| `hwnd_var` | string | "" | 窗口变量 |
| `remark` | string | "" | 备注 |

### 4.2 引用语法

在其他节点参数中使用 `@书签名.属性` 引用：

```
x = @商店按钮.x
y = @商店按钮.y
mode = @商店按钮.mode
```

也支持 `${}` 语法：
```
x = ${商店按钮.x}
```

### 4.3 实时解析

- 每次引用时实时解析坐标
- window/relative 模式：调用 `get_window_client_origin(hwnd)` 实时查询窗口位置
- 窗口拖动后坐标自动跟随
- screen 模式：直接使用存储的坐标值
