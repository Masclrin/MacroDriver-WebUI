# 项目定位与设计原则

## 1. 产品定位

MacroDriver WebUI 是一款面向**游戏玩家与自动化爱好者**的本地宏驱动工具。

### 1.1 核心场景

| 场景 | 描述 |
|------|------|
| 战斗自动化 | 检测怪物 → 自动攻击 |
| 状态监视 | 血条监视 → 自动吃药 |
| BOSS 应对 | BOSS 动作识别 → 自动闪避 |
| 通用自动化 | 重复操作、定时任务、条件触发 |

### 1.2 目标用户

- 中文母语者
- 技术水平：中等
- 需要**可视化节点编辑器**，而非手写代码
- 部分用户有一定编程基础（理解变量、条件判断等概念）

## 2. 核心设计原则

### 2.1 可靠性（第一优先级）

- 自动化脚本执行期间**不能崩溃**
- 异常必须被捕获并记录，不得导致进程退出
- 所有分支线程异常不影响主流程和其他分支

### 2.2 精确性

- 宏动作（按键/鼠标）延迟必须低，使用 Interception 驱动或 SendInput
- 节点执行延迟可以有少量，但必须**统一延迟**，每次运行的抖动偏差要小到几乎感觉不到
- 等待精度达到 0.1ms 级别（`precise_sleep_v5`）
- 坐标解析每次实时查询窗口位置（window/relative 模式），确保窗口移动后坐标自动跟随

### 2.3 直观性

- 节点含义一目了然，中文显示名
- 节点分类清晰（动作/检测/控制/变量/工具）
- 前端支持拼音搜索节点
- 复杂概念通过文档/手册解释，不在 UI 上过度简化

### 2.4 灵活性

- 支持 Fork/Join/Race 并发模型
- 支持嵌套并发（Scope Tree）
- 支持插件扩展（manifest.json + backend.py + node.js）
- 支持变量系统、条件判断、循环、状态机

## 3. 技术架构概览

```
webui/                    前端（HTML/JS 节点编辑器）
bridge/                   前后端桥接层（API）
automation/               新自动化引擎
  ├── engine.py           执行引擎核心
  ├── compiler.py         图解析与编译
  ├── registry.py         节点注册表
  ├── nodes/              节点定义
  ├── handlers/           节点执行逻辑
  └── detection/          检测子系统（截图/颜色/OCR/图片匹配）
engine/                   底层原子能力
  ├── precision.py        精确引擎（sleep/绑核/优先级）
  ├── input_sendinput.py  输入原语（SendInput/Interception）
  └── coordinate.py       坐标解析器
core/                     核心基础设施
  ├── plugin_manager.py   插件管理器
  └── plugin_context.py   插件上下文
宏执行框架3.2.py          旧宏引擎（被新引擎调用）
plugins/                  插件目录
```

## 4. 双轨执行模型

新引擎采用双轨执行模型：

| 轨道 | 用途 | 执行方式 |
|------|------|----------|
| 轨道 1（新引擎直执行） | 原子动作节点、检测节点、控制流 | 新引擎直接调用底层原语 |
| 轨道 2（旧引擎托管） | 旧格式宏脚本（`.json`） | 新引擎调用旧引擎 `execute_macro_once` |

轨道 2 调用时，新引擎传递 `options` 覆盖部分参数（speed_factor、timeline_mode、random_delay、auto_release_modifiers），其余参数 fallback 到旧引擎全局变量。

## 5. 文件格式

| 格式 | 扩展名 | 用途 |
|------|--------|------|
| 自动化脚本 | `.auto.json` | 新引擎节点图（含 variables、settings、graph） |
| 旧宏脚本 | `.json` | 旧引擎宏（被新引擎 `call_script` 节点调用） |

自动化脚本内部结构：
```json
{
  "variables": { "var_name": { "init": value } },
  "settings": { "execution_profile": "standard" },
  "graph": {
    "nodes": [...],
    "connections": [...]
  }
}
```

## 6. 执行档案 (Execution Profile)

| 档案 | Interception 键盘 | Interception 鼠标 | 进程优先级提升 | 线程绑核 |
|------|-------------------|-------------------|----------------|----------|
| lite | 否 | 否 | 否 | 否 |
| standard | 否 | 否 | 是 | 否 |
| precision | 是 | 是 | 是 | 是 |

通过 `graph.settings.execution_profile` 选择，默认 `standard`。
