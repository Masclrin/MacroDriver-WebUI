# 状态机 / 多条件检测 —— 改造说明（面向使用者）

> 版本：v3.3.1　|　目标：把这两个"过于难用"的控制节点，按**用户视角**重新讲清楚并修好。
> 结构未变（输入/输出端口一致），存储格式未变（阶段仍是 `→` 连接的字符串），**旧脚本兼容**。

---

## 一、为什么要改（原来的问题）

| 节点 | 原来的问题 |
|------|-----------|
| 序列检测 | 名字叫"序列/顺序检测"，实际却是"**所有条件同时满足**才放行"（AND 门闸），**名实不符** |
| 状态机 | ① 阶段名只是标签、所有阶段**共用同一个 cond**；② **没接 cond 会无限死等**（表现为卡死）；③ **cond 为假时不 sleep，忙等 100% CPU**；④ 没有超时；⑤ `fail_state` 填错**静默**变成"失败也前进"，反直觉 |

---

## 二、多条件检测（原"序列检测"）

**它是什么**：一个"汇合门闸"——把所有接进来的 `cond` 条件**同时为真**才走 `pass`，否则按重试/超时走 `fail`。
**它不是**"按顺序逐个检测"（这是它原来最容易被误解的地方）。

| 参数 | 含义 |
|------|------|
| 重复检测 | 是=反复检测到满足；否=只检测一次，不满足立即走 `fail` |
| 最大检测次数 | 最多检测多少次（配合检测间隔≈最长等待）。例：100 次 ×100ms ≈ 最多等 10 秒；0=不限次数 |
| 检测间隔(ms) | 每次检测之间的间隔，越小响应越快、越占 CPU |
| **总超时(ms)**（新增） | 直接表达"整体最多等多久"，超过就走 `fail`。0=只用"最大检测次数"；填了以本项为准 |

**未接 cond 时**：现在**立即报错走 `fail`**（原来会白等到次数耗尽，默认约 10 秒）。

---

## 三、状态机

**它是什么**：按你写的**阶段列表**从第 1 个开始逐个推进；每个阶段用 `cond` 判断能否前进，走完最后一个阶段输出 `done`。

**怎么用（新交互）**：
- **阶段列表**：在属性面板里点「添加阶段」，逐行填名字，还能上下移动、删除 —— 不用再手写 `→`。
  节点上只读显示执行顺序，如 `待机 → 攻击 → 冷却 → 待机`。
- **失败回退阶段**：从阶段列表里**下拉选择**（不用手填）。留空=不回退。
- **单阶段超时(ms)**（新增）：某阶段一直等不到 `cond` 为真时，按"失败"处理，避免无出口的等待。0=不超时。
- **判定间隔(ms)**：每隔多久判定一次。

**判定规则（已理顺）**：

| cond | 行为 |
|------|------|
| 为真 | 前进到下一阶段 |
| 为假 + 有失败回退 | 回到所选阶段重新开始 |
| 为假 + 无失败回退 | **停在当前阶段继续等待**（原为"失败也前进"，已改为更符合直觉的等待） |
| 阶段超时 | 能回退到别的阶段就回退，否则前进（**保证一定取得进展**） |
| **未接 cond** | **立即报错并放行 `done`**（原来会永久死等） |

**示例**：阶段 `待机 → 攻击 → 冷却`，失败回退 `待机`
→ cond 为真就依次推进；攻击或冷却阶段 cond 为假就回到"待机"重来；全部走完输出 `done`。

## 四、本次修复清单

- 状态机未接 `cond` 不再无限死等（改为报错 + 走 `done`）
- 状态机等待分支统一 `sleep`，**杜绝忙等**（实测等待 0.5s 时 CPU 占用比 ≈ 3%，此前接近满载）
- 状态机新增 `stage_timeout_ms`；`fail_state` 填错给出告警日志 + 面板橙色提示
- 状态机失败语义理顺（无回退时原地等待而不是前进）
- 多条件检测未接 `cond` 立即 `fail`；新增 `timeout_ms`
- 两节点参数补齐独立标签与通俗说明；新增"阶段列表 / 失败回退"两种可视化编辑器
- 新增回归测试 `automation/tests/test_control_nodes.py`（8 项，全部通过）

## 五、遗留问题（本次未改，建议后续决策）

1. **异步宏终止走错分支**：`调用宏(异步)` 被"动作控制→停止指定任务"终止时，本应走"中断"分支，
   实际因任务池把状态覆写成 `completed` 而走了"完成"分支（`automation/engine.py`）。
2. **`target_task` 下拉误导**：把同步阻塞的"执行子脚本"也列为可停止对象，但它不注册任务池，
   `停止/暂停指定任务` 对它无效。
3. **ESC 无法终止"调用宏"子宏**：ESC 属旧引擎另一套监听，与编辑器"停止/F8"互不相通。
