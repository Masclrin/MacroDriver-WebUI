# 测试点（Breakpoint）使用方法与影响

> 对应功能：动作编辑小窗的「测试点运行」（工具栏按钮 `#btnRunFromBreakpoint`）
> 相关文件：`webui/modules/editor/index.js::runFromBreakpoint`、`macro_io/parser.py::run_macro_slice`

---

## 一、它解决什么问题

长宏（几百上千行）调试时，每次改完都要从头跑到出错位置，浪费大量时间。
测试点让你**只跑关心的那一段**：

```
从「第 N 个测试点」执行到「下一个测试点」（不含），没有下一个就跑到底。
```

---

## 二、怎么设测试点

**只有一个入口：点行号。**

动作列表每行的**行号**就是开关：

| 状态 | 外观 | 含义 |
|---|---|---|
| 未标记 | 普通灰色行号（如 `7`） | 不是测试点，默认零视觉噪声 |
| 已标记 | **浅橘黄底、深色字**的数字（如 `19`） | 是测试点 |

- 点击行号 → 切换标记状态，**立即生效，无需保存**，也无需重载或双击。
- 已标记的行号鼠标移上去会**加深橘黄**（而不是变透明），保证始终看得清。
- 只有**顶层动作行**的行号可点；`loop` 内部子行、`loop_end` 行的行号不可点
  （避免嵌套行号与顶层下标混淆）。
- 浅色主题下用浅橘黄底 + 深棕字；深色主题下用浅橘黄底 + 近黑字 —— 两种主题都不刺眼。

---

## 三、怎么跑

1. 在动作列表里**选中**一个动作（点一下行，左栏参数区会载入它）。
2. 点工具栏的 **「测试点运行」**。
3. 执行区间按下面的规则推导：

```
起点 = 从"当前选中行的行号"开始往后找，遇到的第一个测试点
终点 = 起点之后的第一个测试点（不含终点这一行）
       如果后面没有测试点了 → 终点 = 宏末尾
```

举例（测试点设在第 1、19、40 行）：

| 当前选中行 | 实际执行区间 |
|---|---|
| 第 3 行 | 19 → 39（含 19，不含 40） |
| 第 1 行 | 1 → 18 |
| 第 25 行 | 40 → 末尾 |
| 第 50 行（在所有测试点之后） | 回到第一个测试点：1 → 18 |

起点行**本身会执行**，终点行**不执行**（因为终点是下一个区间的起点）。

---

## 四、同一宏里设多个测试点，有什么影响

**没有负面影响，正是设计意图。** 多个测试点把宏切成若干段，每段的起点就是逐段调试的入口。

具体影响：

1. **逐段验证**：设 1 / 19 / 40 三个点后，可以反复单独跑 19→39 这一段，
   不用重跑前 18 行。段与段之间互不干扰。
2. **测试点是"文档级"状态，不是文件内容**
   - 它存在内存里（`tab.breakpoints`，一个 `Set`），**不会写进 `.json` 宏文件**。
   - 所以：分享宏给别人的时候，别人看不到也拿不到你的测试点。
   - 切换小窗（pane）不丢；但**关闭标签页 / 重开程序就没了**，需要重设。
   - 因此**测试点不影响脏标记**（tab 的 `dirty` 不会因为设测试点而变红）。
3. **不改变宏本身的执行语义**：正常点击「运行宏」时，测试点被完全忽略，
   宏还是从头到尾跑。测试点只在点「测试点运行」时才起作用。
4. **多测试点的实际代价只有一个**：如果你要跑的是"最后一段"，
   而当前选中行靠前，会从靠前的测试点开始 —— 所以**先选中目标段起点附近的行**再点运行，
   语义最符合直觉。

## 五、实现细节（排查问题时看）

- 测试点存的是**顶层行下标**（字符串形式，如 `"19"`），只认 `.` 之前的部分，
  所以即使将来支持嵌套行，也只会取顶层段。
- 「测试点运行」调用后端 `run_macro_slice(rel_path, from_index, to_index)`：
  1. 读取宏文件全部行；
  2. 切出 `rows[start:end]`；
  3. 写到**源文件同目录**的临时文件 `.<名字>.__testrun.json`
     （必须同目录，否则宏里的 `import` 相对路径会解析失败）；
  4. 交给 `宏执行框架3.2.py::run_macro_file_once()` 执行；
  5. **加载/编译完成后立即删除**临时文件。
- 执行线程会注册进 `active_macros`，所以 **「停止全部宏」/「全局暂停」对测试运行同样有效**。
- `_list_macro_files` 会跳过 `.` / `__` 开头的文件，所以临时宏不会出现在宏列表里。
- 若区间为空（终点 ≤ 起点），会提示「测试区间为空（结束点需在起点之后）」。

## 六、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 点了「测试点运行」提示"请先在动作行左侧点出测试点" | 该宏还没设任何测试点，点行号设一个 |
| 提示"测试区间为空" | 起点即最后一个测试点，后面没有更靠后的测试点可作终点 → 检查是否只设了一个点且选中的是它 |
| 跑的范围和我预期不符 | 起点是"选中行往后第一个测试点"，不是选中行本身；想看区间就对着行号橙色行数一下 |
| 重开程序后测试点没了 | 预期行为，测试点不落盘 |
