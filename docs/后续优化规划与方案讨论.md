## 二、Q1：附加宏指令（`ext`）——方向与方案

### 2.1 目标拆解

- 原生可解析、可执行；可被可视化编辑
- 与「宏编辑器 / 执行器 / 自动化执行节点 / 插件」形成**区分与统一**
- 落地场景：原神**帧数切换**、**联网状态**（正常/断网/弱网/强网）、**帧数模拟**（待定）
- 高精度、低延迟；简单文本指令存于 json；可移交插件或外部软件（Rin-launcher）
- 不改变通用 Windows / 游戏自动化 / 宏执行的内核本质；倾向**插件形式**实现

### 2.2 推荐方案 A：内联命名空间指令 + 扩展注册表 + 描述符驱动可视化

**表达形式**（与核心指令显式区分）

```json
["ext", "fps.lock", 30]
["ext", "net.set", "weak"]
["ext", "frame.sim", {"fps": 30, "mode": "pace"}]
```

**三段式**

1. **解析层**：`lenient_json` 已能容错；新增"原始行保留"（见 Q2.8），未识别行不丢。
2. **编译/派发层**：新增 `EXT_HANDLERS` 注册表（对标 `automation` 的 `NODE_HANDLERS`）。  
   `compile_macro` 只多一个查表分支；命中则把 handler 编入同一条 QPC 时间线（保证精度），  
   未命中 → 保留原始行 + 告警（不再静默丢弃）。
3. **可视化层**：每条 ext 指令携带一份**描述符 schema**（与插件 `params_schema` 同构）。  
   前端只写**一个通用渲染器**，插件注册新指令即自动出现在"动作插入器"并有参数表单。

**委派**：handler 由**插件**提供（`plugins/<id>/manifest.json` 增加 `ext_commands` 声明，  
`backend.py` 用注册钩子注入）。核心保持通用，特殊功能全落插件。

### 2.3 备选

- **B：纯插件节点** —— 放弃时间线内联精度，**不满足**"高精度低延迟内联"，仅作补充。
- **C：独立指令文件 `*.ext.json`** —— 用 `["ext_import", "xxx.ext.json"]` 引入（镜像现有 `import`），  
  适合**批量/复用**，可作为 A 的附加能力。

### 2.4 待定点（需你拍板）

| # | 待定              | 说明                                                                              |
| - | --------------- | ------------------------------------------------------------------------------- |
| 1 | 同步 / 异步语义       | 时间线是否等待 handler 完成？建议：默认同步（发 RTSS 键=微秒级）；网络整形等长耗时用 `async:true` fire-and-forget |
| 2 | 命名空间            | `["ext","域.动作",...]` vs 更简短的 `["@fps",30]`。建议前者（可读、可分组、好排障）                     |
| 3 | "帧数模拟"定义        | ①RTSS 限帧 ②帧边界 busy-wait 对齐 ③合成帧延迟注入 —— 三者实现与代价差别很大                              |
| 4 | 网络状态实现          | Windows 下需外部整形器（WinDivert/防火墙规则/进程级限速），最"重"的一块，需定 IPC 协议                        |
| 5 | Rin-launcher 契约 | 命令行参数 / 本地 socket / 文件监视，需与其现有接口对齐                                              |

## 三、Q2：宏编辑页实用性更新（逐项）

> 前置认知：**宏的编辑/执行有多种形态** —— ① 宏编辑页（编辑器 + 绑定执行器）② 自动化图的"执行节点"  
> （自带块编辑器 `webui/modules/auto/editor/block-editor.js`）。因此本次改造应把"动作列表编辑器"  
> 抽成**可复用组件**，供两处共用（这也是 Q1 里 ext 行复用的基础）。

| # | 需求                 | 现状                                                                                   | 建议                                                          |
| - | ------------------ | ------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| 1 | **多标签**            | 单文档：`state.editorRows` / `state.selectedMacro`，打开即覆盖                                 | 引入 `state.editorTabs[]`，每个标签自带 `rows/selection/展开态/脏标记/滚动位` |
| 2 | **焦点为主的编辑**        | 单一全局表单绑到 `state.selectedActionPath`                                                  | 表单绑定"聚焦标签页的选中项"，切换标签时按该标签状态重渲染                              |
| 3 | **跨标签拖拽**          | `state.draggedActionPath` 仅含单文档路径                                                    | 拖拽负载加 `tabId`；跨标签落点时深拷贝动作进目标标签                              |
| 4 | **标签双击重命名**        | 无                                                                                    | 需定语义：改**文件名**（走 `rename_macro`，与现有"重命名当前宏"一致）vs 仅改标签显示名     |
| 5 | **重载仅针对选中标签**      | `#btnReloadEditor` 重载 `state.selectedMacro`                                          | 改为只重载活动标签                                                   |
| 6 | **move_to 参数适配**   | `#actionType`（`index.html:265`）**无 move_to、也无 scroll**；`ACTION_FORM_UI/DEFAULTS` 同样缺 | 补 move_to（X/Y/时长）、scroll（滚动量）；并在"选择栏"可视化改参                  |
| 7 | **测试点（断点）**        | 宏编辑器**无**；但自动化图**已有**断点机制（节点 `_breakpoint` → `run_automation(graph, breakpoints)`）   | 镜像该设计：标记动作→"从此处执行到断点/末尾"。v1 用切片生成临时宏跑通现有执行器                 |
| 8 | **未解析行保留原文 + 可编辑** | 解析失败**丢弃**；未知指令被压缩重序列化                                                               | 引入 `{__raw:"..."}` 行模型：解析失败/未知 → 保留原文；前端渲染可编辑的原文行；保存原样写回    |

**"选择栏"** 建议同时承载：动作类型下拉（含 move_to/scroll/ext）、参数表单、以及"从测试点执行"入口。

## 四、状态机：是否要"多状态条件分别输入 / 失败回退"

- **失败回退**：v3.3.1 已做（`fail_state` 下拉 + 单阶段超时 `stage_timeout_ms` + 等待不忙等）。
- **多状态条件分别输入**：**尚未提供** —— 当前 `states` 是多阶段共用一个 `cond`。  
  若要"每阶段独立条件"，需改**存储格式**（`states` 由 `→` 字符串 → `[{name, cond_ref, timeout}]`），  
  **属破坏性变更**，必须带**旧格式迁移**。建议放到"难"档，先定格式再动手。
- 可顺带解决：每阶段**独立超时**、**独立回退目标**（现在回退是全局一个）。
