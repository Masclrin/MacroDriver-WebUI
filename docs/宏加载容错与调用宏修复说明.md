# 宏加载容错 与 "调用宏" 修复说明（v3.3.2）

面向使用者，说明本次针对三条反馈的处理结果。

---

## 一、逗号不再"卡死"宏（执行 / 编辑全程容错）

### 以前的毛病
- **执行**宏时（`load_macro_recursive`）用的是严格 `json.loads`：
  - 动作**结尾多一个逗号** → 整份宏加载失败；
  - 两条动作之间**漏写逗号** → 整份宏加载失败；
  - loop 循环体里最后一条子动作多/少逗号 → 同样失败。
- **编辑器**读取时，两条动作之间漏写逗号会被**合并成一条**（然后解析失败、被静默丢弃），
  表现为"动作莫名少了几条"。

### 现在
新增宽松解析器，以下写法**全部可正常加载**，且注释会被保留：

```json
[
    // 注释也可以
    ["kd","shift",50]         // ← 漏写逗号，OK
    ["ku","shift",430],
    ["loop", 2, [
        ["kd","w","2f"],
        ["ku","w",0],         // ← 循环体里多写逗号，OK
    ]],
]
```

> 合法 JSON 的解析结果与标准解析**完全一致**，不会改变既有宏的语义。

覆盖范围：宏执行、宏编辑器读取、导入/导出、格式探测、轨迹化简工具。

## 二、"调用宏"节点的动作编辑模块现在真的能用

### 以前的毛病
"编辑动作块"读写的是节点上的一个 `actions` 属性，但：
- 这个属性不在节点定义里、**执行器根本不读它**（执行读的是 `path` 指向的宏文件）；
- 它用的指令集（`left_click`、`key_press`…）与**真实宏指令**（`kd`/`ku`/`md`/`mu`…）对不上。
→ 打开永远是空列表，保存也没用。

### 现在
点「编辑动作块」会**直接读取节点所选宏文件的内容**并可视化展示，用真实宏指令编辑：

| 可编辑项 | 说明 |
|---------|------|
| 按下/抬起按键 | `kd` / `ku`，按键名带补全（w/a/s/d…、space、shift、f1…） |
| 按下/抬起鼠标 | `md` / `mu`，左/右/中键下拉选择 |
| 等待 | `wait`，支持毫秒或帧延迟（如 `2f`） |
| 视角移动 | `view`，dx / dy / 时长 |
| 移动到坐标 | `move_to`，X / Y / 时长 |
| 滚轮 | `scroll` |
| 导入子宏 | `import` |
| 循环 | `loop`，可嵌套、可增删子动作 |
| 注释 | `note`，保存时写成 `// 注释` |

每条动作可**上移/下移/删除**，改完点「保存到宏文件」写回该 `.json`（脚本编译缓存按文件修改时间自动失效，**立即生效**）。
节点没选宏文件时会提示先去属性面板选择。

## 三、"调用宏(异步)"：随流程图结束而终止 —— 属既定设计（未改动）

核查结论：`调用宏(异步)` 节点本身**执行正常**。之所以"看起来没执行"，是因为
**流程图到达结束节点即终止全部**：

- `flow/end`（结束节点）会 `stop_event.set()` + `task_pool.stop_all()`；
- `execute_graph` 收尾 `finally` 同样会 `task_pool.stop_all()`。

异步宏跑在后台线程，主流程一旦走到结束节点就会把它一并终止 —— 这是**预期设计**。

> 曾按"缺陷"临时改过该逻辑（结束节点不再停任务、收尾等待异步完成），**已全部回退**，保持原设计。

**如果你的流程图里异步宏需要真正跑完**，应先让主流程在异步宏执行期间保持运行，例如：

- 用「等待条件 / 条件循环 / 计数循环」占住主流程，直到异步宏该结束；
- 或用「动作控制」显式把控任务生命周期（`暂停指定任务` / `恢复指定任务` / `停止指定任务`）。

直接"启动异步宏 → 走到结束节点"的图，异步宏会被立刻终止，这不是 bug。
