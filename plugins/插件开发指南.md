# 宏驱动 自动化编辑器插件开发指南

---

## 一、系统概述

宏驱动采用**插件式架构**。每个插件一个独立文件夹，后端 Python 动态加载，前端 JavaScript 注册节点。

**三层通信：**
- **后端加载**：`PluginManager.scan(plugins/)` 扫描目录 → 读取 `manifest.json` → 加载 `backend.py` → 调用 `register()`
- **前端加载**：浏览器调用 `pywebview.api.list_plugins()` → 获取 `node.js` → 执行 `window.__plugin_nodes__` → 注册到工具箱
- **运行时执行**：引擎遇到 `plugin/xxx` 节点 → `PluginManager.execute()` → `backend.py execute(action, params, context)` → `context.emit()` → 前端 `onPluginEvent()`

---

## 二、插件目录结构

```
plugins/
└── notify/                    ← 文件夹名 = 插件 ID
    ├── manifest.json          # 必须，声明元信息与节点列表
    ├── node.js                # 必须，定义节点UI、参数、回调
    └── backend.py             # 可选，定义后端逻辑（可自定义文件名，在 manifest 中指定）
```

## 四、node.js 前端节点定义

### 4.1 基本结构

```javascript
var nodes = {
  'plugin/notify_popup': {
    display_name: '消息弹窗',
    color: '#a855f7',
    category: 'plugin',
    icon: 'fa-solid fa-bell',
    backendAction: 'notify_popup',     // 对应 backend.py 的 action
    inputs:  [{name:'in', type:'flow'}],
    outputs: [{name:'next', type:'flow'}],
    params_schema: { /* 见 4.2 */ },

    // 【可选】前端执行（仅模拟执行时触发，实际运行时由后端处理）
    onExecute: function(params) { /* ... */ },

    // 【可选】接收后端 context.emit 的事件
    onPluginEvent: function(eventName, eventData) {
      if (eventName === 'notify_popup_shown') { /* 处理 */ }
    }
  }
};
window.__plugin_nodes__ = nodes;  // 必须导出
```

> **重要**：`onExecute` 仅在**模拟执行（调试模式）**时调用，实际运行自动化流程时不会调用（走后端 `execute`）。
> 所有插件的 `onPluginEvent` 都会被广播调用，必须在内部通过 `eventName` 精确过滤。

### 4.2 params_schema 参数类型

```javascript
params_schema: {
  title:       { type: 'string', label: '标题', default: '提示', varRef: true },
  count:       { type: 'number', label: '次数', default: 1, min: 0, max: 100, varRef: true },
  mode:        { type: 'enum',   label: '模式', default: 'a', options: ['a', 'b', 'c'] },
  enable:      { type: 'bool',   label: '启用', default: true },
  volume:      { type: 'slider', label: '音量', default: 0.8, min: 0, max: 1, step: 0.1 },
  rect:        { type: 'region', label: '区域', default: [0,0,0,0], coordMode: true },
  save_path:   { type: 'string', label: '路径', format: 'path', browseType: 'folder' },
  accent:      { type: 'string', label: '颜色', format: 'color', default: '#ff0000' }
}
```

**type 汇总：**

| type | 渲染控件 | 特殊属性 |
|------|---------|---------|
| `string` | 文本框 | `varRef`, `format: 'color'/'path'`, `browseType: 'folder'/'file'/'template'` |
| `number` | 数字框 | `varRef`, `min`, `max`, `step` |
| `enum` | 下拉框 | `options: [...]`, `varRef` |
| `bool` | 开关 | — |
| `slider` | 滑块 | `min`, `max`, `step` |
| `region` | 坐标区域 | `coordMode: true`, `default: [x,y,w,h]` |

**通用属性：** `label`（必须）、`default`、`description`、`showWhen`（条件显示表达式，见 4.6）

### 4.6 showWhen 条件显示语法

```javascript
params_schema: {
  stop_mode:  { type: 'bool', label: '停止信号', default: false },
  threshold:  { type: 'number', label: '阈值', default: 0.8, showWhen: 'stop_mode=false' },
  count:      { type: 'number', label: '数量', default: 1, min: 0, max: 5 },
  item_0:     { type: 'string', label: '项目1', default: '', showWhen: 'count>=1' },
  item_1:     { type: 'string', label: '项目2', default: '', showWhen: 'count>=2' }
}
```

**支持运算符**：`=`、`!=`、`>=`、`<=`、`>`、`<`

**多条件**：逗号分隔表示 AND，同字段连续段表示 OR。如 `showWhen: 'stop_mode=false,combo_count>=1'` 表示 stop_mode 为 false **且** combo_count >= 1 时显示。

> **注意**：`bool` 类型在 showWhen 中使用小写 `true`/`false`，Python 后端可用大写 `True`/`False`（`_normalizeSchema` 自动转换）。

### 4.3 inputs / outputs 端口

```javascript
inputs:  [{name:'in', type:'flow'}, {name:'data_in', type:'data'}],
outputs: [
  {name:'next', type:'flow'},        // 默认流程输出（必须有）
  {name:'success', type:'flow'},     // {"ok": true} 走此分支
  {name:'fail', type:'flow'},        // {"ok": false} 走此分支
  {name:'result', type:'data'},      // 数据端口，接收 check_results["result"]
]
```

- `type: 'flow'` — 流程控制端口
- `type: 'data'` — 数据端口
  
**引擎路由**：`ok: true` → `success` 端口（无则走 `next`）；`ok: false` → `fail` 端口（无则走 `next`）。

### 4.4 自定义出口路由（flow_port）

插件可以通过返回值中的 `flow_port` 字段，**指定走哪个自定义输出端口**，突破默认的 `ok/success/fail/next` 路由限制：

```javascript
// node.js 中定义多个 flow 输出端口
outputs: [
  {name:'next', type:'flow'},       // 正常完成
  {name:'timeout', type:'flow'},    // 超时
  {name:'fail', type:'flow'},       // 失败
  {name:'result', type:'data'}      // 数据端口
]
```

```python
# backend.py 中通过 flow_port 指定出口
def execute(action, params, context):
    # ... 监控逻辑 ...
    if idle_timed_out:
        return {"ok": True, "flow_port": "timeout", "check_results": {"count": 5}}
    if error_occurred:
        return {"ok": False, "error": "原因"}  # 走 fail 端口
    return {"ok": True, "check_results": {"count": 5}}  # 走 next 端口
```

**路由优先级**：
1. 如果返回值包含 `flow_port` 且节点定义了该端口 → 走指定端口
2. 如果 `flow_port` 指定的端口不存在 → 回退到 `next`
3. 如果无 `flow_port` → 按原有 `ok: true/false` → `success/fail/next` 逻辑

## 五、backend.py 后端逻辑

### 5.1 必须导出的函数

```python
def register():
    return [{"action": "notify_popup", "name": "弹窗通知"}]

def execute(action, params, context):
    if action == "notify_popup":
        return _handle(params, context)
    return {"ok": False, "error": f"未知动作: {action}"}
```

### 5.2 返回值规范

```python
{"ok": True}                                                     # 成功
{"ok": True, "data": {...}}                                      # 携带数据
{"ok": True, "set_variables": {"var": val}}                      # 设置全局变量（下游 ${var} 引用）
{"ok": True, "check_results": {"result": True, "confidence": 0.9}}  # 数据端口输出
{"ok": False, "error": "原因"}                                   # 失败
```

> **check_results 的 key 必须与 node.js 中 `outputs` 的 data 输出端口 `name` 一致！**
> `set_variables` → 全局变量表（`${变量名}` 引用）；`check_results` → 写入检查结果表（数据端口连线或 `${节点ID.端口名}` 引用）。

### 5.3 PluginContext 完整 API

`execute(action, params, context)` 中的 `context` 提供以下方法：

**事件与日志：**
| 方法 | 说明 |
|------|------|
| `context.emit(event, data)` | 向前端推送事件，前端 `onPluginEvent` 接收。事件名建议 `插件id_事件名` 避免冲突 |
| `context.log(level, msg)` | 写入日志，level: `debug`/`info`/`warning`/`error` |

**变量接口：**
| 方法 | 说明 |
|------|------|
| `context.get_variable(name, default)` | 读流程变量 |
| `context.set_variable(name, value)` | 写流程变量（跨插件共享） |
| `context.get_check_result(key, default)` | 读取检查结果（如 `"12.result"`） |
| `context.get_graph()` | 获取当前流程图对象 |
| `context.get_exec_context()` | 获取底层执行上下文（高级用途） |

**截图/屏幕：**
| 方法 | 说明 |
|------|------|
| `context.capture_screen([x,y,w,h])` | 截图，参数为**物理像素坐标**，自动使用 DXGI（如已启用）或回退 mss。返回 `numpy.ndarray` (BGR) |
| `context.get_screen_size()` | → `{"width": int, "height": int}` |

> **截图回退链**：插件调用 `capture_screen()` 时自动按以下优先级选择截图方式：
> 1. **DXGI**（流程图中包含截图源节点时）→ 高性能后台采集，小区域(<500×500)自动走 BitBlt
> 2. **BitBlt**（无截图源节点时）→ Windows GDI 截图，无需截图源节点即可使用，DPI 缩放正确
> 3. **mss**（BitBlt 失败时兜底）→ 跨平台截图库
>
> 插件无需关心截图方式，`context.capture_screen()` 自动选择最优路径。

> **⚠️ 坐标存储约定（重要，2026-05 更新）**：
> - **screen 模式**：前端存储**物理像素坐标**（所见即所得），`resolve_region("screen", rect)` 直接返回不缩放。插件可直接传给 `capture_screen()`。
> - **window 模式**：前端存储**物理像素坐标**（2026-05 重构后从逻辑坐标改为物理坐标），`resolve_region("window", rect, hwnd)` 在运行时加上窗口原点。属性面板原样显示物理坐标。
> - **relative 模式**：前端存储 **0~1 比例值**，`resolve_region("relative", rect, hwnd)` 在运行时乘以窗口物理尺寸加原点偏移。属性面板显示比例值。
>
> **坐标全链路（2026-05 新模型）**：
> ```
> 拾取器(tools.js) ──→ 物理像素直存 → 写入属性
> 属性面板(renderers.js) ──→ 原样显示物理坐标（window模式不再做DPI转换）
> 后端(coordinate.py) ──→ resolve_region: 存储值 + 窗口原点 = 物理坐标 → capture_screen
> ```
>
> 插件应统一调用 `resolve_region(mode, rect, hwnd)` 处理坐标转换，无需关心内部细节：
> ```python
> from engine.coordinate import resolve_region
> rect = params.get("rect", [0, 0, 0, 0])
> phys_region = resolve_region(mode, rect, hwnd)  # 自动处理三种模式
> frame = context.capture_screen(list(phys_region))
> ```
>
> **坐标浏览器**：坐标浏览器是主窗口内的浮动面板（非弹出窗口）。插件节点的坐标标记在浏览器上显示需要 `_extract_plugin_coord_rules` 正确提取坐标（当前只支持 region 4元组，point 坐标暂不支持显示）。

### 5.3a 坐标模式后端模板（推荐复制使用）

当插件需要截图功能时，应支持三种坐标模式。以下是完整的后端模板：

```python
def _get_hwnd(params, context):
    hwnd_val = params.get("hwnd_var", "")
    if not hwnd_val:
        return None
    try:
        return int(hwnd_val)
    except (ValueError, TypeError):
        pass
    if isinstance(hwnd_val, str) and hwnd_val.startswith("${") and hwnd_val.endswith("}"):
        var_name = hwnd_val[2:-1]
        val = context.get_variable(var_name, "")
        if val:
            try:
                return int(val)
            except (ValueError, TypeError):
                pass
    val = context.get_variable(str(hwnd_val), "")
    if val:
        try:
            return int(val)
        except (ValueError, TypeError):
            pass
    return None

def _resolve_region(mode, rect, hwnd=None):
    try:
        from engine.coordinate import resolve_region
        return resolve_region(mode, rect, hwnd)
    except Exception:
        return tuple(int(v) for v in rect)

def execute(action, params, context):
    mode = params.get("mode", "screen")
    hwnd = _get_hwnd(params, context)
    rect = params.get("rect", [0, 0, 0, 0])
    phys_region = _resolve_region(mode, rect, hwnd)
    frame = context.capture_screen(list(phys_region))
    # ...
```

**对应 node.js 参数定义：**

```javascript
params_schema: {
  mode:     { type: 'enum', label: '坐标模式', default: 'screen',
              options: ['screen', 'window', 'relative'], coordMode: true },
  rect:     { type: 'region', label: '检测区域', default: [0,0,0,0], coordMode: true },
  hwnd_var: { type: 'string', label: '窗口变量', default: '', varRef: true,
              description: 'window/relative模式需要指定窗口句柄变量名' }
}
```

> **关键**：`mode` 参数标记 `coordMode: true` 后，前端拾取器会自动根据当前模式进行坐标转换；`hwnd_var` 标记 `varRef: true` 后，引擎会自动解析 `${变量}` 引用。

**窗口/UI：**
| 方法 | 说明 |
|------|------|
| `context.find_window(title=None, class_name=None)` | 返回 hwnd |
| `context.get_window_rect(hwnd)` | → `{"x","y","width","height"}` |
| `context.show_desktop_popup(title, msg, x, y, duration_ms=3000)` | 桌面置顶弹窗 |

**输入/多媒体：**
| 方法 | 说明 |
|------|------|
| `context.get_mouse_position()` / `set_mouse_position(x,y)` | 鼠标位置 |
| `context.play_sound(file=None, freq=800, dur=200)` | 播放音频 |

**高精度等待：**
| 方法 | 说明 |
|------|------|
| `context.precise_sleep(seconds)` | 高精度等待，替代 `time.sleep`。自动响应停止/暂停事件，返回 `True`=正常完成, `False`=被中断 |

> **precise_sleep 详解**：使用项目高精度引擎 (`engine/precision.py`) 实现，三阶段混合等待（粗睡眠→细睡眠→忙等）+ 自适应偏差补偿，长时间运行后精度趋近 ±50us。自动从执行上下文获取 `stop_event` 和 `pause_event`，流程停止时立即返回 `False`，暂停时暂停等待。`precision` 模块不可用时自动回退到 `time.sleep`。
>
> ```python
> def execute(action, params, context):
>     # 等待 50ms，精度远高于 time.sleep(0.05)
>     ok = context.precise_sleep(0.05)
>     if not ok:
>         return {"ok": False, "error": "被停止中断"}
>
>     # 等待 1.5 秒
>     ok = context.precise_sleep(1.5)
>     if not ok:
>         return {"ok": False, "error": "被停止中断"}
> ```
>
> **适用场景**：轮询间隔、按键间延迟、锁帧等待等对时序精度有要求的场景。

**图像检测：**
| 方法 | 说明 |
|------|------|
| `context.find_image(template, region, threshold)` | 模板匹配 → `{"found","x","y","confidence"}` |
| `context.check_color(x, y, "#RRGGBB", tolerance)` | 颜色检测 → `{"match","actual_color","diff"}` |

> **兼容性**：所有接口可选，使用前用 `hasattr(context, 'xxx')` 检查可用性并为旧版本提供回退。

### 5.4 耗时操作（重要）

**使用 `threading.Thread` 避免阻塞引擎：**

```python
import threading
def execute(action, params, context):
    def background():
        result = do_long_task(params)
        context.emit("task_done", {"result": result})
    threading.Thread(target=background, daemon=True).start()
    return {"ok": True}
```

## 七、变量解析机制（⚠️ 必读）

### 7.1 varRef 自动解析

当 `params_schema` 中设置了 `varRef: true` 时，**引擎会自动解析** `${变量}` 引用，插件 `execute()` 收到的参数已经是解析后的值。

```python
def execute(action, params, context):
    # params["title"] 已经是解析后的值，如 "操作完成于 2025-01-15 14:30:00"
    title = params.get("title")  # ✅ 无需手动解析
```

**未设置 `varRef: true` 的参数保持原始字符串，需手动解析。**

### 7.2 内置变量（完整列表）

| 变量名 | 说明 | 示例值 |
|--------|------|--------|
| `${timestamp}` | 时间戳(ms) | `"1736927400000"` |
| `${timestamp_s}` | 时间戳(s) | `"1736927400"` |
| `${date}` | 日期 | `"2025-01-15"` |
| `${time}` | 时间 | `"14:30:00"` |
| `${datetime}` | 日期时间 | `"2025-01-15 14:30:00"` |
| `${datetime_compact}` | 紧凑日期时间 | `"20250115_143000"` |
| `${random}` | 随机数 | `"38472"` |
| `${random_int}` | 随机整数 | `"582931"` |
| `${year}` / `${month}` / `${day}` | 年/月/日 | `"2025"` / `"01"` / `"15"` |
| `${hour}` / `${minute}` / `${second}` | 时/分/秒 | `"14"` / `"30"` / `"00"` |
| `${weekday}` | 星期(0=周一) | `"3"` |
| `${pid}` | 进程ID | `"12345"` |

### 7.3 变量引用语法

| 语法 | 含义 | 示例 |
|------|------|------|
| `${变量名}` | 流程变量 | `${my_counter}` |
| `${内置变量}` | 系统内置 | `${datetime}` |
| `${节点ID.端口名}` | 节点数据端口 | `${12.result}` |
| `${书签名.key}` | 书签键值 | `${pos.x}` |
| `@书签名.x` | 书签坐标引用 | `@target.x`（`coordMode` 区域中使用） |

### 7.4 手动解析模板（需要时复制使用）

以下模板用于解析**未设置 `varRef` 的参数**中的 `${变量}`：

```python
import re, time

_BUILTIN = {
    "timestamp": lambda: str(int(time.time()*1000)),
    "timestamp_s": lambda: str(int(time.time())),
    "date": lambda: time.strftime("%Y-%m-%d"),
    "time": lambda: time.strftime("%H:%M:%S"),
    "datetime": lambda: time.strftime("%Y-%m-%d %H:%M:%S"),
    "datetime_compact": lambda: time.strftime("%Y%m%d_%H%M%S"),
    "random_int": lambda: str(__import__('random').randint(0,999999)),
    "year": lambda: time.strftime("%Y"), "month": lambda: time.strftime("%m"),
    "day": lambda: time.strftime("%d"), "hour": lambda: time.strftime("%H"),
    "minute": lambda: time.strftime("%M"), "second": lambda: time.strftime("%S"),
    "pid": lambda: str(__import__('os').getpid()),
}

def resolve_vars(value, context):
    if not isinstance(value, str): return value
    matches = re.compile(r'\$\{([^}]+)\}').findall(value)
    if not matches: return value
    if len(matches)==1 and value==f"${{{matches[0]}}}":
        return _resolve_single(matches[0], context)
    result = value
    for vn in matches:
        result = result.replace(f"${{{vn}}}", str(_resolve_single(vn, context)))
    try:
        if result.replace('.','',1).replace('-','').isdigit():
            num = float(result); return int(num) if num==int(num) else num
    except: pass
    return result

def _resolve_single(var_name, context):
    if var_name in _BUILTIN: return _BUILTIN[var_name]()
    val = context.get_variable(var_name)
    if val is not None: return _fmt(val)
    if '.' in var_name:
        node_id, port = var_name.split('.',1)
        cr = context.get_check_result(var_name)
        if cr is not None: return _fmt(cr)
        g = context.get_graph()
        if g:
            for nid, n in g.nodes.items():
                if n.type=="utility/bookmark" and n.params.get("name")==node_id:
                    return n.params.get(port,"")
            target = g.nodes.get(node_id)
            if target and target.type.startswith("utility/"):
                try:
                    from automation.handlers import NODE_HANDLERS
                    from automation.engine import PluginRegistry
                    nd = PluginRegistry.get_node(target.type)
                    h = NODE_HANDLERS.get(nd.get("handler")) if nd else None
                    if h: h(target, context.get_exec_context())
                    cr2 = context.get_check_result(var_name)
                    if cr2 is not None: return _fmt(cr2)
                except: pass
    cr = context.get_check_result(var_name)
    if cr is not None: return _fmt(cr)
    return ""

def _fmt(v):
    if isinstance(v, float) and v==int(v): return int(v)
    return v
```

## 八、调试与检查清单

**后端调试**：使用 `context.log("info", msg)`，控制台可见；PluginManager 使用 `logging.getLogger("plugin")`。

**前端调试**（浏览器 F12）：
- 搜索 `[PluginLoader]` 查看加载状态
- `Object.keys(AutomationNodes._nodeDefs).filter(k=>k.startsWith('plugin/'))` 查看节点注册
- 搜索 `[PY->JS]` 确认事件桥接正常
- 在 `onPluginEvent` 开头加 `console.log('[DEBUG]', eventName, eventData)` 追踪

**常见问题：**
| 问题 | 排查 |
|------|------|
| 插件不显示 | 检查 `manifest.json` 的 `nodes` 字段；看控制台加载日志 |
| 无属性面板 | 检查 `window.__plugin_nodes__` 导出和 `params_schema` |
| 后端执行前端无反应 | 检查 `context.emit`；看 [PY->JS] 日志；确认 `onPluginEvent` 事件名过滤 |
| `${变量}` 不解析 | 确认 `varRef: true` 已设置（自动解析）或手动调用了 `resolve_vars()` |
| 首次加载失败 | `loadPlugins` 有 20 次重试（~6s），也可手动刷新 |

**发布前检查清单：**
- [ ] `manifest.json` 中 `id` 与文件夹名一致
- [ ] `node.js` 使用 `var` 而非 `let/const`，导出 `window.__plugin_nodes__`
- [ ] `backend.py` 导出 `register()` 和 `execute()`，使用 `logging.getLogger("plugin.xxx")` 而非 `print()`
- [ ] 事件名格式 `插件id_事件名` 避免冲突
- [ ] 耗时操作用 `threading.Thread` 异步执行
- [ ] 使用 `hasattr(context, 'xxx')` 检查新 API 可用性
