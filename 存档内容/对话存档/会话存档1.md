**问题分析**: 第 1089 行的 `}` 关闭了 if/else if 链，导致第 1090-1092 行（`clearInterval`、置空、显示"执行完成"提示）对所有非错误状态都会执行。这意味着：

- 当后端返回 **PAUSED** 状态时，轮询立即停止并显示"执行完成"提示 -- **错误**
- 当后端返回 **RUNNING** 状态时，轮询也立即停止并显示"执行完成"提示 -- **错误**
- 第 1093 行的 `} else if (st === 'ERROR')` 语法上属于外层 `if (res && res.ok...)` 的 else 分支，导致 **ERROR 状态处理可能不可达**

### 补充说明

1. **`hwnd_var` 参数**：虽然 `varRef: True`，但 handler 中统一通过 `_get_hwnd()` 处理，该函数内部通过 `ctx.safe_get_variable()` 查找变量值，属于替代性变量解析机制，不视为遗漏。
2. **`store_var`/`store_number`/`store_hwnd_var`/`counter_var` 参数**：这些是**输出变量名**（指定结果存入哪个变量），handler 中使用 `_extract_var_name()` 提取变量名后写入，这是正确行为。对这些参数标记 `varRef: True` 是为了让前端显示变量选择器，而非需要解析变量引用值。
3. **`target_branch` 参数**（stop_branch/pause_branch/resume_branch）：通过专用函数 `_resolve_target_branch()` 处理 `${var}` 语法，属于替代性解析机制，不视为遗漏。
4. **`input_var`/`cond_var` 参数**：这些是变量名引用（指定读取哪个变量的值），handler 手动提取变量名并查找值，属于正确的特殊处理。
5. **前端 `_normalizeSchema()` 自动添加 varRef**：前端 [nodes.js:121-126](file:///c:/Users/1/Downloads/宏驱动 webui 2.7.7/webui/modules/auto/nodes.js#L121-L126) 会自动为 `tolerance`、`threshold`、`change_threshold`、`area_ratio_threshold`、`pyramid_levels`、`rect`、`region`、`hwnd_var`、`store_var` 等参数名添加 `varRef: True`。即使后端定义未显式标记，前端也会启用变量选择器。这意味着上述遗漏的影响范围可能比后端定义中显式标记的更广。
