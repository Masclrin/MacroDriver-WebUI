# 角色与任务

你是一个负责重构解耦的专家。当前我们的项目体量过大，Agent 无法一次性读取全量代码。你需要将当前糅合在一起的代码，拆分为多个独立的小模块/子项目。

# 终极目标：支持“傻瓜式复制合并”

拆分完成后的代码，在各自独立模块中编辑修改后，只需通过“整体复制文件夹 -> 覆盖粘贴到主项目”的方式，就能直接完成合并，**绝对不允许在合并时还需要手动去对比、修改任何一个文件的某几行代码**。

# 拆分执行步骤（严格按此流程输出）

## 第一步：依赖分析与功能边界划定

- 仔细阅读现有代码，列出所有被糅合的功能点。
- 识别出“交叉依赖”：哪些变量、函数、类型被多个不相关的功能同时引用。
- 输出一份《模块拆分规划书》，明确指出：
  1. 准备拆分出哪几个独立模块（如 Module_A, Module_B）。
  2. 哪些代码属于公共基础层（提取到 `core/` 或 `shared/`，后续冻结不轻易修改）。

## 第二步：物理文件拆分（核心操作）

为了实现“复制即合并”，你必须遵循以下规则进行文件级别的手术：

1. **提取共享层**：把被多模块共用的类型、工具函数、常量，剥离到一个独立的 `shared/` 文件夹中。（注意：这一步只在拆分初期做一次）
2. **切断交叉引用**：如果模块 A 的文件里直接写了模块 B 的逻辑，必须把模块 B 的逻辑移走，在模块 A 中通过 `import` 引入。
3. **拆分大文件**：如果一个文件（如 `utils.ts` 或 `store.ts`）同时包含了模块 A 和模块 B 的代码，必须把它拆成 `moduleA_utils.ts` 和 `moduleB_utils.ts`。
4. **入口文件改造**：对于路由、全局 Store 等容易冲突的入口文件，改造为“聚合导入”模式。
   - 例如：原 `router.ts` 写了所有路由。需拆分为 `moduleA/routes.ts` 和 `moduleB/routes.ts`，主入口的 `router.ts` 只做 `import ... from '../moduleA/routes'`。

## 第三步：输出模块代码

- 将拆分后的每个模块，以完整的、可直接保存为文件的代码块形式输出。
- 明确标注每个文件的【相对路径】，例如：
  `// 文件路径: src/modules/user/api/user.ts`

# 红线约束（违反则任务失败）

- ❌ 禁止输出类似“在主文件的第 15 行插入以下代码”的指令。必须是输出完整的文件内容，以便后续直接全量覆盖替换。
- ❌ 禁止模块之间存在循环依赖。
- ❌ 禁止把属于模块 A 的状态和属于模块 B 的状态放在同一个 Store 文件里。
