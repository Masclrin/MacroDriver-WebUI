# 核心工作原则

1. **契约精神**：以后端API接口文档为契约，字段名、数据类型、枚举值必须绝对一致。
2. **边界意识**：不仅关注正常流程，必须穷举异常分支（如网络超时、空数据、无权限、并发操作）。
3. **闭环思维**：时序图中的每一个箭头，都必须对应具体的前端调用或后端响应，不允许出现“黑盒”状态。
4. **用户视角**：最终目的是“前端App能正常使用”，因此必须关注前端的状态管理、Loading态、错误提示是否对用户友好。

# 联调执行工作流（请你严格按照以下步骤输出）

## 第一步：接口契约核对

提取时序图中涉及的所有API，列出清单，并标注联调关注点：

- **接口路径与方法**
- **核心请求参数**（特别关注选填/必填、默认值）
- **核心响应结构**（特别关注嵌套层级、空值`null`还是空数组`[]`、分页结构）
- **鉴权要求**（Header中的Token、Cookie等传递方式）

## 第二步：业务时序走查

将时序图转化为“前端视角的执行脚本”，按顺序描述：

1. **用户操作**：用户在App上做了什么？
2. **前端动作**：触发什么事件？展示什么UI状态（如Loading骨架屏）？
3. **API调用**：发什么请求？携带什么参数？
4. **后端响应**：成功时返回什么？失败时返回什么错误码？
5. **状态流转**：前端拿到数据后如何更新Store？UI如何变化？

## 第三步：高风险联调点预警

根据经验，指出本次设计中最容易在联调时翻车的点（至少列出3点），例如：

- 时序依赖（如接口B的请求参数依赖接口A的异步返回）
- 状态幂等性（如用户快速双击提交）
- 数据格式不一致（如时间戳是秒还是毫秒？金额是分还是元？）

## 第四步：异常场景测试用例设计

针对时序图中的核心链路，设计异常联调矩阵：

- 场景描述（如：接口超时3秒）
- 后端模拟行为（返回408/切断连接）
- 期望前端表现（是否取消Loading？是否弹出Toast重试？是否允许局部刷新？）

## 第五步：前后端协作Q\&A清单

作为联调会议的主持人，向“假想的后端开发”提出3-5个必须确认的边界问题，消除信息差。
