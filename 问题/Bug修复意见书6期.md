### A6-001 [🔴🔴🔴 致命] `detection/check_image` — 金字塔匹配ROI切片行列顺序错误

| 项目 | 内容 |
|------|------|
| **原始编号** | N6-001 |
| **问题位置** | [detection.py:282](file:///g:/宏引擎/宏驱动 webui 2.7.7/automation/handlers/detection.py#L282) |
| **问题描述** | 金字塔匹配时 ROI 切片使用 `roi_x2` 作为行终止索引而非 `roi_y2`，导致裁剪区域错误或数组越界崩溃 |
| **影响范围** | 所有使用金字塔匹配（pyramid_levels > 1）且设置非零 ROI 区域的用户 |
| **复现路径** | 用户拖出 check_image → 设置 pyramid_levels > 1 → 设置非零 ROI → 执行 → 匹配结果错误或崩溃 |
| **修复方案** | 将 `img[roi_y1:roi_x2, roi_x1:roi_x2]` 改为 `img[roi_y1:roi_y2, roi_x1:roi_x2]` |
| **附加改进** | store_var 参数 label 从"位置变量"改为更清晰的描述，添加 placeholder 提示存储内容格式 |

### A6-002 [🔴🔴🔴 致命] `engine.py` — _resolve_value 对未定义变量的替换策略不一致

| 项目 | 内容 |
|------|------|
| **原始编号** | N6-002 |
| **问题位置** | [engine.py:396-450](file:///g:/宏引擎/宏驱动 webui 2.7.7/automation/engine.py#L396-L450) |
| **问题描述** | 单变量引用 `${unknown}` 返回原字符串，多变量混合引用中未定义变量替换为 `"0"`，行为完全不可预测 |
| **影响范围** | 所有使用变量引用的用户，特别是参数中包含未定义变量名的情况 |
| **复现路径** | 在任意节点的 varRef 参数输入 `${不存在的变量}` → 执行 → 观察结果不一致 |
| **修复方案** | 统一替换策略：所有未定义变量统一替换为空字符串 `""`，并记录 warning 日志 |

### A6-003 [🔴🔴 严重] `preset/preset_read_text` — capture_screen 调用缺少 ctx 参数

| 项目 | 内容 |
|------|------|
| **原始编号** | N6-006 |
| **问题位置** | [preset.py:91](file:///g:/宏引擎/宏驱动 webui 2.7.7/automation/handlers/preset.py#L91) |
| **问题描述** | capture_screen(region) 缺少 ctx 参数，截图无法响应 stop_event |
| **影响范围** | 使用 preset_read_text 节点的用户，停止脚本时截图操作可能继续执行 |

### A6-004 [🔴🔴 严重] `compiler.py` — 多个 start 节点时报错但仍然执行

| 项目 | 内容 |
|------|------|
| **原始编号** | N6-012 |
| **问题位置** | [compiler.py:82-84](file:///g:/宏引擎/宏驱动 webui 2.7.7/automation/compiler.py#L82-L84) |

### A6-005 [🔴 高] `control/call_script_async` — 异步回调可能在 ctx 已清理后触发

| 项目 | 内容 |
|------|------|
| **原始编号** | N6-017 |
| **问题位置** | [control.py:171-209](file:///g:/宏引擎/宏驱动 webui 2.7.7/automation/handlers/control.py#L171-L209) |
| **问题描述** | 异步线程中的 `_execute_flow` 回调可能在主流程结束后触发，对已清理的 ctx 操作导致异常 |
| **影响范围** | 使用 call_script_async 且异步任务耗时较长的情况 |
| **修复方案** | 在异步回调开头检查 `ctx.stop_event.is_set()` 或 ctx 状态，如已停止则跳过回调 |
