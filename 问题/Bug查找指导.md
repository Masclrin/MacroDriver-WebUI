# Bug 查找指导 — 拒绝项汇总与判定参考

> **目的**: 指导Bug审查人员避免重复提出已被拒绝的问题，减少无效审查工作量
> **更新日期**: 2026-05-02
> **判定依据**: `docs/设计标准/` 全部文件，特别是 `08-已知缺陷与待办功能.md`

---

## 一、判定原则

在提出Bug之前，审查人员应先对照以下原则进行自检：

1. **查设计标准**: 先查阅 `docs/设计标准/` 对应模块的文档，确认行为是否为设计意图
2. **查拒绝清单**: 对照本文档的拒绝项清单，确认是否已被前几期拒绝
3. **区分Bug与Feature**: 功能缺失是Feature Request，行为与设计意图不符才是Bug
4. **区分Bug与技术债务**: 冗余代码、架构不优但当前不影响功能的属于技术债务

## 三、高频拒绝模式

以下模式在多期审查中反复出现并被拒绝，审查人员应特别注意：

### 3.1 "X节点缺少Y参数" → 多数是 Feature Request

| 模式 | 拒绝原因 | 正确做法 |
|------|----------|----------|
| 节点缺少某个参数 | 功能增强请求，非Bug | 记入Feature Request，不作为Bug |
| 节点缺少某种模式 | 设计取舍，非所有模式都需要 | 查设计标准确认是否为有意省略 |
| 节点缺少动画/缓动 | 非核心场景，增加复杂度 | 评估收益后再决定 |

### 3.2 "X行为与Y不一致" → 需区分设计意图

| 模式 | 判定方法 |
|------|----------|
| 不同节点的同名参数默认值不同 | 查设计标准确认是否为不同场景有意设计（如 mouse_click vs mouse_move 的 move_duration） |
| 前端 fallback 与后端定义不一致 | 若 `_normalizeSchema` 自动修复则非Bug，记为可维护性改进 |
| 检测节点与监视器节点参数不一致 | 监视器与检测是不同子系统，参数差异可能是设计意图 |

### 3.3 "X不响应暂停" → 监视器不暂停是设计意图

| 组件 | 是否应暂停 | 依据 |
|------|-----------|------|
| 延迟/等待节点 | 是 | 08-6.1节 |
| 检测节点 wait 轮询 | 是 | 08-6.1节 |
| 控制节点轮询 | 是 | 08-6.1节 |
| 同步宏短路径 | 是 | 08-6.1节 |
| **监视器后台线程** | **否** | **08-6.1节明确：监视器模型不允许暂停恢复** |

### 3.4 "flow/end 全局停止" → 设计意图，不是Bug

设计标准 `02-并发模型` 8.3节和 `08-已知缺陷` 5节明确说明：
- `flow/end` 全局终止是设计意图
- 任何分支到达结束节点 = 任务完成
- 如仅需结束当前分支，使用 `control/stop_branch`

### 3.5 "隐式变量/自动创建变量" → 特性，不是Bug

- 工具运算节点自动创建 `{id}_out` 变量是特性，方便下游引用
- 用户若需改名，再使用一次设置变量节点
- 不应作为"变量污染"Bug提出

### 3.6 "颜色/视觉不一致" → 多数是设计意图或低优先级

- 起始/结束节点颜色特殊化是有意设计，强调其特殊性
- 分类颜色与节点颜色不一致是视觉调优，非功能性Bug
- 小地图颜色 fallback 是可接受行为

### 3.7 "API模式 vs Fallback模式不一致" → Fallback为主要使用场景

- 前端 fallback 是离线/主要使用场景，功能更完整
- 后端 API 定义用于在线同步节点定义，属于轻度展示场景
- 若 fallback 有某属性（如 coordRef、pickable、无 showWhen 限制）而后端缺失：
  - 不影响用户实际使用（fallback 覆盖了绝大多数场景）
  - 属于可维护性改进，非功能性 Bug
  - 如需修复应优先改 Fallback 模式对齐后端，而非反向操作

## 四、复制粘贴连线规则

**设计意图**（08-5节）：粘贴节点时仅保留被复制节点之间的连线，连到外部节点的连线不保留。

**理由**：
- 外部节点可能已被删除或修改，保留外部连线可能导致悬空引用
- 用户粘贴到不同脚本时，外部节点不存在

**审查人员注意**：不要将"粘贴不保留外部连线"作为Bug提出。

## 五、审查自检清单

提出Bug前，逐项确认：

- [ ] 是否查阅了 `docs/设计标准/` 对应模块文档？
- [ ] 是否对照了本文档的拒绝项清单？
- [ ] 该问题是行为与设计意图不符（Bug），还是功能缺失（Feature）？
- [ ] 该问题是否属于"高频拒绝模式"中的某一种？
- [ ] 静默失败/返回默认值的问题，是否确认设计标准未说明此行为是有意的？
- [ ] "不一致"类问题，是否确认不是为不同场景的有意设计？
